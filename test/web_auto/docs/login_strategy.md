# 登录与验证码自动化策略

## 优先级 A：测试环境免验证码（推荐长期方案）

- 后端提供测试账号白名单或内网 IP 白名单，登录接口跳过验证码校验。
- 自动化通过 `CAPTCHA_BYPASS_HEADER_KEY/VALUE` 或白名单账户直接登录。
- 优点：稳定、可持续、便于 CI 无人值守执行。

## 优先级 B：会话态复用（次优）

- 首次登录成功后保存 `storageState` 到 `.auth/storage-state.json`。
- 后续执行复用登录态，避免每轮都触发验证码。
- 适合验证码无法短期改造，但登录态可较长时间有效的场景。

## 优先级 C：人工一次验证（过渡）

- 设置 `LOGIN_MODE=manual_captcha`，脚本在登录页 `pause` 等待人工完成验证码。
- 登录成功后自动保存会话态，再继续冒烟/回归执行。
- 适合临时验证与联调阶段，不建议作为长期 CI 方案。

## 不建议方案

- 尝试破解滑块/图形验证码（维护成本高，稳定性差，可能触发合规风险）。
