## 2. 本地开发环境

### 2.1 应用端口（当前 `.env`）

```text
FRONTEND_PORT=8000
ADMIN_PORT=8001
BACKEND_PORT=5000
ENVIRONMENT=development
DEBUG=true
```

| 项 | 值 |
|----|-----|
| 类型 | PostgreSQL |
| 主机 | `localhost` |
| 端口 | **5446** |
| 用户 | `postgres` |
| 密码 | `qidianspacetime` |
| 库名 | `stock_analysis` |

连接串（分项等价）：

```text
postgresql+psycopg2://postgres:qidianspacetime@localhost:5446/stock_analysis
```

```bash
psql -h localhost -p 5446 -U postgres -d stock_analysis
```

```text

```

### 2.4 历史/备选本机连接（`.env` 注释）

曾出现过的备选串（端口 **8432**，密码含特殊字符 `$`）：

```text
postgresql+psycopg2://postgres:qidianspacetime$91@localhost:8432/stock_analysis
```

仅在本机实际监听 8432 时使用；当前默认开发库为 **5446**。

### 2.5 本地启动顺序（简要）

1. PostgreSQL（5446）
2. 后端 API：`python` 启动 backend_api（5000）
3. 用户前端：`python start_frontend.py`（8000）
4. 管理端：admin 开发服或静态服（8001）
5. 采集调度（按需）：`python start_backend_core.py` / `backend_core.data_collectors.main`

| 项 | 说明 |

| 项 | 典型值 / 说明 |
|----|----------------|
| 类型 | PostgreSQL 12+ |
| 库名 | `stock_analysis` |
| 用户 | `postgres`（或现场专用账号） |

## 5.1 环境数据同步（策略 / 观察 / 基本信息 / 板块 / 行情 / 复权因子）

用于本地与生产之间同步配置与基础市场数据（不含 `*_signal_trace`）。

| 角色 | 做什么 |
|------|--------|
| **生产** | 管理端「环境数据同步」→ 生成/启用 Sync Key；开放 `GET/POST /api/env-sync/v1/*`（Bearer / `X-Env-Sync-Key`） |
| **本地** | 填写生产 Base URL + 同一 Key；点 **Pull**（生产→本地）或 **Push**（本地→生产） |

**可同步范围（管理端按分组勾选）：**

| 分组 | 内容 | 日期范围 |
|------|------|----------|
| 策略参数 | GMS/URT/RPE/SBBR 配置、GMS 运行时 | 否 |
| 交易观察/正式 | 各策略观察股、历史、正式交易、SBBR 储备箱 | 否 |
| 股票基本信息 | A股 / 港股 `stock_basic_info*` | 否（全表 upsert） |
| 板块信息 | 行业/概念基本信息 + 成分股 | 否（全表 upsert） |
| 行情数据 | A股 / 港股 `historical_quotes*` | **必须**指定 `start_date`～`end_date` |
| 复权因子 | A股/港股 `stock_adj_factor`（港股 5 位码 + `source=akshare_sina_hk_qfq`） | **可选**：不填=全库；填写则按 `trade_date` 过滤（默认跨度可达约 11 年） |

- 默认勾选仅为「策略 + 观察」；全选会包含基本信息/板块/行情/复权因子；勾选行情后须填区间
- 行情单次跨度上限：`ENV_SYNC_QUOTE_MAX_DAYS`（默认 366）；复权因子按区间时：`ENV_SYNC_ADJ_FACTOR_MAX_DAYS`（默认 4018）；超限请分批
- 复权因子全库同步：仅勾选 `stock_adj_factor` / `adj_factors` 且不传日期；与行情同批时复权因子会共用行情日期区间
- 网关：`GET /api/env-sync/v1/export?modules=...&start_date=&end_date=`；管理端 Pull/Push body 同样传 `start_date`/`end_date`
- 组快捷项：`strategy_configs` / `trade_observe` / `gms_trade` / `basic_info` / `board_info` / `quotes` / `adj_factors` 等
- 用户按 `username` 对齐；目标端**不存在的用户**对应行会跳过
- 策略配置按 `name` upsert；观察股按 `(user, market, code)`；行情按 `(code, date)`；复权因子按 `(code, trade_date, source)`；基本信息按 `code`
- 表：`env_sync_server_config` / `env_sync_client_config` / `env_sync_audit_logs`
- 迁移：`python migrations/add_env_sync_tables.py`
- Push 到生产前请确认已备份
- 本地出站调用使用标准库 `http.client`（部分 Windows 环境 `httpx` 连生产会 WinError 10054）
- 若返回 401：生产端未启用/未配置与本地一致的 Sync Key
- 若生产缺表（如 `urt_trade_observe_stocks`）：在生产执行 `python migrations/add_urt_trade_tables.py`（及对应策略迁移）；未建表时 export 会跳过该表并继续其余模块
- 若 Push 报 **HTTP 413 Request Entity Too Large（nginx）**：
  1. 生产 nginx 的 `location /api/` 将 `client_max_body_size` 调到 **200m**（仓库模板已更新；改完后 `nginx -t && reload`）
  2. 本地管理端 Push 已按 bundle 分批上传；若仍 413，缩小勾选范围（尤其行情缩短 `start_date`/`end_date`）
  3. 确认生效的是生产机正在使用的 conf，而不仅是仓库里的示例文件
- 若 Push `import[adj_factors]` / `import[board_data]` 报 **HTTP 502**：
  1. 多为生产导入超时（逐行 ORM / gunicorn 超时，板块成分股整包尤甚）；本地 Push 默认每块 400 行，遇 502/413 会自动对半拆分重试
  2. **必须重启本地 API** 后改动才生效；生产部署含批量 UPSERT 的版本并重启
  3. 可在本地 `.env` 设置 `ENV_SYNC_PUSH_ROW_CHUNK=100` 强制更小分块
  4. 生产 nginx `proxy_read_timeout` 建议 ≥ 600s；并检查 gunicorn `--timeout`（过短会直接 502）
  5. 若拆到约 50 行仍 502：多半是生产缺表/缺列或 API 崩溃，查生产错误日志


**生产 `/api/admin/env-sync/*` 返回 404 时：**

1. 看启动日志：`环境同步路由注册失败`（常见：`No module named 'httpx'`）
2. 生产 API 所用 Python 环境安装：`pip install httpx==0.26.0`，再重启 API
3. 确认已部署 `backend_api/env_sync/`，并执行：`python migrations/add_env_sync_tables.py`
4. 启动日志应出现「环境同步路由注册成功」；未登录访问应变 401/403，不应再是 404
