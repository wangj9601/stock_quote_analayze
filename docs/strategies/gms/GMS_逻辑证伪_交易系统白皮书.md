## 摘要

本白皮书定义 **GMS × 逻辑证伪** 一体化交易体系的设计目标、业务规则与系统落地路径。

- **GMS（均值引力与动量突变策略）** 负责 **「选什么、什么形态值得交易」**——通过量化指标识别左侧均值收敛与右侧动量溢出机会。
- **逻辑证伪应对系统** 负责 **「买错了怎么认、怎么退、看对了怎么拿」**——将买入理由写成可检验条件，并为每条理由设定失效规则与分层应对动作。

二者结合，形成 **选股引擎 + 执行风控引擎** 的完整闭环，目标不是「每次看对」，而是 **看错时有规则、亏得可控、看对时拿得住**。

## 1. 设计背景与问题陈述

### 1.1 现有 GMS 体系的能力与缺口

当前系统已具备较完整的 GMS 能力链路：

| 环节 | 现有能力 | 主要模块 |
|------|----------|----------|
| 选股扫描 | 全市场/板块/自选股 GMS 信号筛选 | `GMSStrategyEngine`、选股 API |
| 信号追溯 | 历史指标时间轴、得分明细 | `gms_signal_trace`、Trace 页面 |
| 交易观察 | 信号加入观察池，保存快照 | `GmsTradeObserveStock` |
| 正式交易 | 观察转入、记录入场/出场 | `GmsFormalTrade` |
| 回测验证 | 信号命中率、交易模拟 | `backtest_runner` |
| 执行复盘 | 交易思路与执行记录 | `TradeExecutionLog` |

**缺口在于**：

1. **入场与出场逻辑不统一**：GMS 回测出场以百分比止损、跟踪止损为主；选股页的 `sell_signal` 仅作参考，与实盘执行未打通。
2. **买入理由不可追溯**：正式交易记录了 `signal_snapshot_json`，但未结构化绑定「证伪条件」与「分层应对规则」。
3. **A 股 T+1 与收盘确认未制度化**：回测默认「信号日次日开盘价入场」，实盘缺少统一的收盘确认规范。
4. **环境过滤部分落地**：选股侧已对「主行业板走弱」做软减分与展示（见 §6.3）；大盘极端阴跌等仍为建议项。

### 1.2 逻辑证伪系统的定位

逻辑证伪不是替代 GMS 选股，而是 **GMS 信号进入实盘后的规则层**：

```
GMS 回答：这只票、这个形态，是否值得赌？
逻辑证伪回答：我赌的这个形态，什么时候已经不算数了？
```

## 2. 系统哲学与核心原则

### 2.1 双引擎分工

| 引擎 | 职责 | 输出 |
|------|------|------|
| **GMS 阿尔法引擎** | 形态识别、评分排序、信号产生 | 左侧/右侧买点、综合总分、指标快照 |
| **逻辑证伪执行引擎** | 预案生成、失效检测、分层应对 | 证伪条件、应对级别、退出确认 |

### 2.2 五条执行原则（RULES BEFORE TRADE）

1. **预测 → 预案**：每笔交易买入前必须书面化入场逻辑，禁止「感觉看涨」式下单。
2. **情绪 → 规则**：盘中波动不替代确认；A 股 T+1 环境下以 **收盘确认** 为准。
3. **证伪 ≠ 固定比例止损**：止损位优先取自 **结构失效位**（均线、平台、突破位），百分比止损仅作兜底。
4. **分层应对**：轻微异常、关键失守、逻辑完全反向，对应不同动作，避免「所有波动都卖出」。
5. **成熟系统的目标**：不是每次看对，而是 **看错时有规则**。

## 3. 总体架构

### 3.1 三层体系

```
┌─────────────────────────────────────────────────────────────┐
│  第一层：GMS 选股引擎（Alpha）                                │
│  扫描 → 左侧/右侧判定 → 综合评分 → 信号列表/观察池           │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  第二层：逻辑证伪预案层（Plan）                               │
│  入场逻辑结构化 → 自动生成证伪模板 → 四问预案 → 收盘确认入场  │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  第三层：持仓执行与复盘层（Execute & Review）                 │
│  日/周收盘检测 → 分层应对 → 正式交易更新 → 执行日志复盘       │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 与现有数据流对接

```
GMS 选股页 / 信号追溯
        │
        ▼
GmsTradeObserveStock（观察池 + signal_snapshot_json）
        │
        ▼  [新增] 证伪预案生成 + 四问确认 + 收盘确认
        │
GmsFormalTrade（正式交易 + [新增] falsification_plan_json）
        │
        ▼  [新增] 每日收盘后 GMS 指标刷新 → 证伪检测
        │
出场更新 / 分层减仓
        │
        ▼
TradeExecutionLog（复盘：是否严格执行、是否情绪化）
```

## 4. GMS 引擎概要（第一层）

> 详细规则见 [GMS策略买点判定标准说明文档](./GMS策略买点判定标准说明文档.md)。

### 4.1 核心指标（观察期 N=20）

| 符号 | 含义 |
|------|------|
| Δ | 宏观位移 = d₂₀ − d₁ |
| d | 20 日均价（MA20） |
| d₂₀ | 周期末收盘价 |
| ratio_d20 | Δ / d₂₀，偏离率 |
| ratio_d1 | Δ / d₁，突变率 |
| volume_ratio | m₂₀ / m，量比 |
| F / Z | 20 日内下跌/上涨天数 |
| fz_ratio | F / Z，数方比 |

### 4.2 买点类型

| 类型 | 策略定位 | 核心特征 | 最高等级 |
|------|----------|----------|----------|
| **左侧（均值收敛）** | 地量吸筹、引力粘合 | F > Z，Δ < 0，\|ratio_d20\| 小，量比低 | S 级 ≥85 / A 级 ≥70 |
| **右侧（动量溢出）** | 放量突破、动量起爆 | d₂₀ > d，Δ > 0，量比高 | 全速切入 ≥90 / 分批买入 ≥80 |

### 4.3 综合总分

```
综合总分 = max(均值收敛态得分, 动量溢出态得分)
```

左、右同时满足时，引擎 **优先归类为左侧**。

### 4.4 现有卖点提示（参考用）

配置见 `gms_config.json` → `exit`：

| 配置项 | 默认值 | 含义 |
|--------|--------|------|
| `overbought_ratio` | 0.15 | 乖离过大提示卖点 |
| `trend_break_days` | 3 | 趋势破坏天数（设计项，单日检测未实现） |

在本体系中，`overbought_ratio` 映射为 **「看对时的止盈/减仓」**，而非证伪退出。

## 5. 逻辑证伪引擎概要（第二、三层）

### 5.1 交易前四问（每笔必答）

| # | 问题 | 内容 |
|---|------|------|
| Q1 | 我为什么买？ | 方向、周期、结构、资金/环境依据 |
| Q2 | 我错在哪里会被证明？ | 可观察、可执行的证伪条件 |
| Q3 | 如果错了，在哪里退出？ | 关键位、确认周期、最大可接受亏损 |
| Q4 | 如果对了，如何处理？ | 加仓、止盈、持有条件 |

### 5.2 三层应对级别

| 级别 | 触发情形 | 默认动作 | 默认仓位调整 |
|------|----------|----------|--------------|
| **L1 轻微异常** | 部分指标走弱，核心结构未破坏 | 减仓观察 | 减 30%～50% |
| **L2 关键失守** | 收盘确认跌破预设结构位，买入逻辑被证伪 | 执行止损 | 清剩余仓位 |
| **L3 逻辑完全反向** | 周期+结构+量能同时转弱 | 清仓停手 | 100% 退出；冷却期禁止同逻辑补仓 |

### 5.3 收盘确认规则（A 股 T+1）

| 级别 | 确认时点 | 用途 |
|------|----------|------|
| **D 日线** | 当日收盘 | 日常证伪检测；避免盘中假跌破 |
| **W 周线** | 周五收盘 | 波段逻辑是否延续 |
| **M 月线** | 月末收盘 | 长期趋势生态是否改变 |

**规则**：盘中触及止损位 **不立即执行**（除非启用「紧急兜底止损」）；以对应级别的 **收盘确认** 为正式触发。

## 6. GMS × 逻辑证伪：规则映射

### 6.1 左侧买点（均值收敛态）

#### 入场逻辑（Q1 系统预填模板）

| 维度 | GMS 条件 | 说明 |
|------|----------|------|
| 周期 | N=20 观察期内 F > Z | 空头时间耗散 |
| 结构 | \|ratio_d20\| < 1.5%（或 S/A 等级直通） | 价格粘合 MA20 |
| 量能 | volume_ratio < 0.8 | 地量洗盘 |
| 位移 | Δ < 0 | 周期内宏观位移为负 |

#### 证伪条件（Q2 系统预填 + 人工确认）

| 买入理由 | 证伪条件 | 级别 | 确认周期 |
|----------|----------|------|----------|
| F > Z 时间耗散 | fz_ratio 回落至 ≤ 1.0，或 Z ≥ F | L1 | 日收盘 |
| 引力粘合 | \|ratio_d20\| > 2.5% 且 3 个交易日收盘未收回 | L2 | 日收盘 |
| 地量洗盘 | 放量下跌（volume_ratio > 1.5）且 Δ 进一步走低 | L3 | 日收盘 |
| 左侧信号有效 | 左侧信号消失且综合分 < 70 | L1 | 日收盘 |
| 评分降级 | 均值收敛态得分从 S/A 跌破 70 | L1 | 日收盘 |

#### 结构止损位（Q3）

| 优先级 | 止损位定义 |
|--------|-----------|
| 1 | MA20（d）下沿 — 与 GMS 结构一致 |
| 2 | 信号日平台/波段低点 |
| 3 | 兜底：入场价下方 5%（与现有回测默认一致） |

#### 看对时的处理（Q4）

| 条件 | 动作 |
|------|------|
| 左侧信号转为右侧信号，且动量分 ≥ 80 | 可加仓（不超过原计划总仓位） |
| \|ratio_d20\| > 15%（overbought_ratio） | 分批止盈 30%～50% |
| 周线结构未破坏 | 继续持有剩余仓位 |

---

### 6.2 右侧买点（动量溢出态）

#### 入场逻辑（Q1 系统预填模板）

| 维度 | GMS 条件 | 说明 |
|------|----------|------|
| 结构 | d₂₀ > d（收盘在均线上方） | 突破均线 |
| 位移 | Δ > 0 | 宏观位移转正 |
| 量能 | volume_ratio > 1.5 | 放量确认 |
| 评分 | 动量溢出态 ≥ 80（全速/分批）或满足无等级触发条件 | 攻击强度 |

#### 证伪条件（Q2）

| 买入理由 | 证伪条件 | 级别 | 确认周期 |
|----------|----------|------|----------|
| 站上 MA20 | **日收盘**跌回 MA20 下方 | L2 | 日收盘 |
| Δ > 0 位移转正 | Δ 重新转负且持续 2 个交易日 | L1 | 日收盘 |
| 放量突破 | 突破后缩量跌回突破位/平台（假突破） | L3 | 日收盘 |
| 动量评分 | 动量溢出态得分跌破 60 且 instant_deviation < 0 | L1 | 日收盘 |
| 推力支撑 | d₂₀ − d 由正转负且连续 2 日 | L2 | 日收盘 |

#### 结构止损位（Q3）

| 优先级 | 止损位定义 |
|--------|-----------|
| 1 | 突破位/信号日阳线低点 |
| 2 | MA20（d） |
| 3 | 兜底：入场价下方 5% |

#### 看对时的处理（Q4）

| 条件 | 动作 |
|------|------|
| 动量分维持 ≥ 80 且 volume_ratio 持续 > 1.2 | 持有；可小幅加仓 |
| \|ratio_d20\| > 15% | 分批止盈 |
| 左侧+右侧共振（先左后右） | 视为趋势升级，放宽持有条件 |

### 6.3 环境过滤层（第三层前置检查）

| 环境条件 | 检测方式 | 动作 | 落地状态 |
|----------|----------|------|----------|
| 大盘极端阴跌 | 指数 N=20 内 F/Z > 2.5 且 Δ < 0 | 所有 GMS 新仓减半；已有仓位 L1 降级 | 未实现 |
| 板块走弱 | 同花顺**主行业板**成分量权基准近 N 日斜率 &lt; 0（斜率不可用时回退当日板块涨跌幅 &lt; 0） | 选股 **软减分** `board_weak`（默认 10 分）并打标签；**不**做硬过滤 | **已实现（选股）** |
| 板块资金流走弱 | 板级主力净流入等 | 拟与斜率组合软降权 | **未采集**（字段预留，二期） |
| 个股相对强度消失 | 个股 5 日涨幅 &lt; 板块指数 5 日涨幅 | L1 减仓观察 | 未实现 |

选股结果字段：`primary_board_code/name`、`sector_slope`、`board_change_percent`、`board_weak`、`board_main_net_inflow`（预留）。

**斜率口径与数据路径（§6.3 补充）：**

- 基准 \(I_t=\sum(close\cdot volume)/\sum(volume)\)，近 N 日（默认 60）线性回归斜率；**板内全成分**（`board_panel_member_limit` 为 `null`/`0` 表示不截断）。
- 行业/概念板无官方日线指数：在**行业板实时行情采集成功后**，用成分股日线合成斜率，分别写入 `industry_board_daily_metrics` / `concept_board_daily_metrics`（`sector_slope` / `sector_slope_window` / `slope_asof_date` / `member_count_used`）。**仅同花顺（`board_code_source=tonghuashun`）**行业板与概念板参与计算/入库；东财/华泰等其它来源一律跳过。概念板无独立实时采集，斜率与行业板对称挂载于同一采集任务之后。
- **行情页列表**只批量读库（不在打开列表时对 ~90 板同步现算）。若库为空（例如采集挂载尚未跑过）：
  1. 行情页「行业板块」工具栏点 **刷新斜率** → `POST /api/market/industry_board/refresh_sector_slopes?board_kind=industry`（默认后台异步全量）；
  2. 或打开单板 **详情**：库中无斜率时现算该板全成分并 upsert，再返回；
  3. 或等下次行业板实时采集成功后的自动 `refresh_board_sector_slopes`。
- GMS enrich **优先读库**；缺失时对同花顺主行业板现算全成分；非同花顺主板块不现算、不判弱（`insufficient_board_data`）。store API 对概念板 + tonghuashun 过滤同样可用，供其它策略复用。

> 注：环境过滤 **不等同于个股证伪**，而是 **全局或板块级的仓位降级 / 选股降权**。

## 7. 完整交易流程（SOP）

### 7.1 阶段一：信号产生与观察

| 步骤 | 动作 | 系统操作 |
|------|------|----------|
| 1 | GMS 选股/追溯发现信号 | 展示左侧/右侧、总分、指标明细 |
| 2 | 用户加入「交易观察」 | 写入 `GmsTradeObserveStock`，保存 `signal_snapshot_json` |
| 3 | 系统自动生成证伪预案草案 | [待实现] 根据 `buy_type` 填充 Q1/Q2 模板 |
| 4 | 用户确认或修改四问预案 | [待实现] 前端表单 + 持久化 |

### 7.2 阶段二：入场确认

| 买点类型 | 入场确认规则 | 说明 |
|----------|-------------|------|
| **左侧** | 信号日后 1～3 个交易日内，日收盘仍满足左侧核心条件 | 避免「信号闪一下」；可等地量确认 |
| **右侧** | 信号日 **日收盘** 站稳 MA20 且 volume_ratio > 1.5 | 突破有效性以收盘为准 |
| **通用** | 环境过滤未触发降级 | 见 §6.3 |

确认通过后：观察池 → **正式交易**（`GmsFormalTrade`），记录 `entry_price`、`position_lots`、证伪预案。

### 7.3 阶段三：持仓监控

| 频率 | 检查内容 | 数据来源 |
|------|----------|----------|
| **每日收盘后** | GMS 指标刷新 → 对照证伪条件 | `gms_signal_trace` / 实时计算 |
| **每周五收盘** | 周线结构是否延续 | 周 K + GMS 指标 |
| **月末** | 长期趋势是否破坏 | 月 K + 20 月线 |

触发应对后：更新 `GmsFormalTrade.status`、`exit_price`；写入 `TradeExecutionLog`。

### 7.4 阶段四：出场与复盘

| 步骤 | 动作 |
|------|------|
| 1 | 记录触发级别（L1/L2/L3）、触发条件、确认周期 |
| 2 | 评估是否严格执行预案（是/偏差较大） |
| 3 | 评估是否存在情绪化操作（无/轻微/严重） |
| 4 | 总结：本次证伪是否合理、GMS 信号质量复盘 |

## 8. 仓位管理规则

### 8.1 初始仓位（与 GMS 评分挂钩）

| GMS 等级 | 左侧 | 右侧 | 建议初始仓位（占单票上限） |
|----------|------|------|---------------------------|
| 最高档 | S 级 ≥85 | 全速切入 ≥90 | 100% |
| 中档 | A 级 ≥70 | 分批买入 ≥80 | 50%～70% |
| 基础档 | 无等级但满足触发条件 | 无等级但满足触发条件 | 30%～50% |
| 环境降级 | 任意 | 任意 | 在上述基础上 ×50% |

### 8.2 分层减仓与加仓

| 事件 | 仓位调整 |
|------|----------|
| L1 轻微异常 | 当前仓位 × 50%（减 half） |
| L2 关键失守 | 清剩余全部仓位 |
| L3 逻辑反向 | 全部清仓 + 5 交易日冷却期 |
| 右侧升级（左→右） | 可加仓至初始计划上限 |
| 止盈（overbought） | 减 30%～50%，保留趋势仓 |

### 8.3 兜底风控

结构止损与百分比止损 **同时生效，取较紧者**：

```
有效止损价 = max(结构止损位, 入场价 × (1 - stop_loss_pct))
```

默认 `stop_loss_pct = 5%`（与现有回测兜底一致）。

## 12. 风险声明

1. 本体系为 **规则化交易框架**，不构成投资建议。
2. GMS 信号基于历史数据与统计规律，**不保证未来有效**。
3. 证伪规则需通过 **回测与实盘样本** 持续验证和调参。
4. A 股存在涨跌停、流动性不足等极端情况，**收盘确认可能无法及时退出**，兜底止损仍需保留。
5. 环境过滤、板块数据质量会影响规则有效性，实施前需确认数据源可靠性。

| 术语 | 定义 |
|------|------|
| GMS | 均值引力与动量突变策略（Gravity & Momentum Shift） |
| 逻辑证伪 | 买入理由被市场数据推翻时的规则化应对 |
| 左侧买点 | 均值收敛态，地量吸筹逻辑 |
| 右侧买点 | 动量溢出态，放量突破逻辑 |
| L1/L2/L3 | 轻微异常 / 关键失守 / 逻辑完全反向 |
| 收盘确认 | 以日/周/月收盘价判定，非盘中即时判定 |
| 结构止损 | 基于 MA20、平台、突破位的止损，非固定百分比 |
