# 五日涨跌幅计算功能说明与实现

本文档整合五日（5 天）涨跌幅计算功能的需求说明、实现总结、修复说明与使用方式。

---

## 一、功能概述

### 1.1 目标

- **业务目标**：为历史行情数据自动或按需计算 5 日涨跌幅，供技术分析与投资决策使用。
- **体验目标**：历史行情每日采集完成后自动计算，用户无需每次人工触发；同时支持手动单只/批量、按日期范围计算及状态查询。

### 1.2 核心特性

- **自动计算**：历史行情采集完成后自动触发 5 日涨跌幅计算（零配置、错误隔离）。
- **手动计算**：支持单只股票、批量、按日期范围、最近 N 天及状态查询。
- **多入口**：采集侧（backend_core/tushare）与 API/Web 侧（backend_api 历史行情接口）均可触发计算。
- **数据验证**：至少 6 个交易日数据才可计算；结果保留 2 位小数；异常与边界有处理。

---

## 二、计算逻辑

### 2.1 公式

```
5日涨跌幅(%) = (当前收盘价 - 5个交易日前收盘价) / 5个交易日前收盘价 × 100
```

### 2.2 规则

- **时间**：5 个**交易日**（非自然日），遇周末自动跳过。
- **起点**：从第 6 个交易日开始才有 5 日涨跌幅。
- **数据要求**：至少 6 天的历史行情（含当日）。
- **精度**：保留 2 位小数；除零、空值等做安全处理。

### 2.3 示例

- 某日收盘价 7.25，5 个交易日前收盘价 7.18 → 5 日涨跌幅 = (7.25 - 7.18) / 7.18 × 100 ≈ 0.97%。

## 三、实现架构与入口

### 3.1 采集侧（自动计算）

- **位置**：`backend_core/data_collectors/tushare/`
- **组件**：
  - `five_day_change_calculator.py` — 核心计算器（单日/批量、状态查询）
  - `historical.py` — 历史采集完成后自动调用计算
  - `calculate_five_day_change.py` — 独立命令行脚本（date/range/recent/status）
- **存储**：`historical_quotes.five_day_change_percent`；操作日志写入 `historical_collect_operation_logs`（如 `operation_type='five_day_change_calculation'`）。

### 3.2 API/Web 侧（手动计算）

- **位置**：`backend_api/`（如 `stock/history_api.py`、`trading_notes_routes.py` 等，以实际项目为准）
- **能力**：按股票代码 + 日期范围计算并更新 5 日涨跌幅；供历史行情页“计算 5 天升跌”按钮或接口调用。
- **前端**：历史行情页选择股票与日期后点击计算；另有独立 Web 计算器页面（如 `frontend/five_day_change_calculator.html`）时可做单只/批量与状态监控。

### 3.3 数据库

- **表**：`historical_quotes`
- **字段**：`five_day_change_percent DECIMAL(8,2)`（或 REAL，以实际迁移为准）
- **扩展**：若字段不存在，可执行 `ALTER TABLE historical_quotes ADD COLUMN five_day_change_percent DECIMAL(8,2);`（或项目提供的迁移脚本）。

## 四、历史问题与修复（最后 5 天无法计算）

### 4.1 问题描述

- 用户选择日期范围（如 2024-01-01 至 2024-01-31）并点击“计算 5 天升跌”后，**范围内最后 5 个交易日的 5 日涨跌幅为空**。
- 原因：计算某日的 5 日涨跌幅需要**该日之前 5 个交易日**的收盘价，但接口只查询了用户给出的 `start_date`～`end_date`，未包含“开始日期之前”的数据，导致范围内末尾几天无法算。

### 4.2 修复思路

1. **扩展查询范围**  
   在计算时，将查询的起始日期向前扩展 5 个**工作日**（即 `extended_start_date = 开始日期前 5 个工作日`），再按 `[extended_start_date, end_date]` 取行情，保证范围内每一天都有“5 天前”的收盘价。
2. **仅更新用户指定范围**  
   只对 `start_date ≤ date ≤ end_date` 的记录做计算并写回 `five_day_change_percent`，不修改范围外数据。
3. **工作日计算**  
   实现“某日期前 N 个工作日”的辅助函数（跳过周六、周日），用于得到 `extended_start_date`。

### 4.3 后端示例逻辑（思路）

```python
extended_start_date = _get_date_before_business_days(start_date_fmt, 5)

```

### 4.4 其他曾修复点（参考）

- **查询条件过严**：若曾仅更新 `five_day_change_percent IS NULL OR = 0`，会导致已有值（如负值）不更新；可改为在指定范围内**一律重算并更新**。
- **前端日期范围**：部分实现中前端将结束日期自动延长 5 个工作日再请求，以便后端能拿到足够数据；后端需支持扩展后的日期范围并仍只更新用户可见范围。

## 五、使用方式

### 5.1 自动计算（推荐）

- 历史行情每日采集任务完成后会自动执行 5 日涨跌幅计算，无需额外配置。
- 依赖：采集侧使用 `backend_core` 的 HistoricalQuoteCollector 并已集成 FiveDayChangeCalculator（见第三节）。

### 5.2 命令行（采集侧）

```bash
# 指定日期
python backend_core/data_collectors/tushare/calculate_five_day_change.py --mode date --date 2025-01-01

# 日期范围
python .../calculate_five_day_change.py --mode range --start-date 2025-01-01 --end-date 2025-01-31

# 最近 N 天
python .../calculate_five_day_change.py --mode recent --days 30

# 状态查询
python .../calculate_five_day_change.py --mode status --date 2025-01-01
```

### 5.3 编程接口（采集侧）

```python
from backend_core.data_collectors.tushare.five_day_change_calculator import FiveDayChangeCalculator
from backend_core.database.db import SessionLocal

session = SessionLocal()
calculator = FiveDayChangeCalculator(session)
result = calculator.calculate_for_date("2025-01-01")
status = calculator.get_calculation_status("2025-01-01")
session.close()
```

### 5.4 Web/API（若存在）

- **历史行情页**：选择股票与日期范围 → 点击“计算 5 天升跌” → 调用后端按范围计算并刷新表格。
- **单只计算**：`POST /api/trading_notes/{stock_code}/calculate_five_day_change`（以实际路由为准）。
- **批量计算**：`POST /api/trading_notes/calculate_all_five_day_change`（以实际路由为准）。
- **Web 计算器**：访问 `frontend/five_day_change_calculator.html`（若保留）进行单只/批量与状态监控。

## 六、性能与运维要点

### 6.1 性能

- 批量更新、事务控制；只计算/更新必要范围；避免重复全表扫描。
- 可在 `(code, date)` 上建复合索引以加速查询与更新。

### 6.2 监控与日志

- 采集侧：`historical_collect_operation_logs` 中 `operation_type='five_day_change_calculation'`，可查影响行数、状态、错误信息。
- 应用日志：计算开始/结束、成功/失败条数、异常信息。

### 6.3 故障排除

- **最后几天仍为空**：确认是否已应用“扩展查询范围 + 仅更新指定范围”的修复；检查 `extended_start_date` 与工作日函数是否正确。
- **部分记录未更新**：检查是否曾用“仅更新 NULL/0”的条件，改为范围内全量重算并更新。
- **计算失败/500**：查数据库连接、历史数据是否连续、收盘价是否有效；查看后端与操作日志。

## 八、总结

- **功能**：5 日涨跌幅 = (当前收盘价 - 5 个交易日前收盘价) / 5 个交易日前收盘价 × 100；至少 6 天数据，保留 2 位小数。
- **自动**：历史采集完成后自动计算（backend_core 集成）；**手动**：命令行、编程接口、历史行情页按钮及 Web/API。
- **修复**：通过“扩展查询范围（开始日期前 5 个工作日）+ 只更新用户指定日期范围”解决最后 5 天无法计算的问题；并避免因“仅更新 NULL/0”导致数据不完整。
- **部署**：保证 `historical_quotes.five_day_change_percent` 已存在；配置好数据库与（若使用）Tushare；按需执行迁移与测试脚本。
