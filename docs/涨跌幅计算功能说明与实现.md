# 涨跌幅计算功能说明与实现

## 功能概述

本系统在历史行情数据采集基础上，提供 **5 日、10 日、60 日涨跌幅** 的自动与手动计算能力：在原有的 5 日涨跌幅之上，扩展支持更全面的多周期涨跌幅分析，并在历史行情采集完成后自动执行计算，无需用户手动触发。

---

## 实现目标

- 历史行情数据采集完成后自动计算 5 日、10 日、60 日涨跌幅
- 支持批量计算和单日计算
- 完善的错误处理和日志记录
- 提供独立的手动计算工具（含命令行与编程接口）
- 计算状态监控和查询
- 数据库迁移与表结构扩展

---

## 核心组件

### 1. 5 日涨跌幅计算器 (FiveDayChangeCalculator)

- **位置**: `backend_core/data_collectors/tushare/five_day_change_calculator.py`
- **功能**: 5 日涨跌幅核心计算逻辑
- **主要方法**:
  - `calculate_for_date()`: 为指定日期计算所有股票的 5 日涨跌幅
  - `calculate_batch_for_date_range()`: 批量计算日期范围
  - `get_calculation_status()`: 获取计算状态
  - `_calculate_single_stock_five_day_change()`: 单只股票计算

### 2. 扩展涨跌幅计算器 (ExtendedChangeCalculator)

- **位置**: `backend_core/data_collectors/tushare/extended_change_calculator.py`
- **功能**: 支持 5 日、10 日、60 日涨跌幅的批量计算
- **主要方法**:
  - `calculate_for_date()`: 为指定日期计算所有股票的扩展涨跌幅
  - `calculate_batch_for_date_range()`: 批量计算日期范围内的涨跌幅
  - `get_calculation_status()`: 查询计算状态和完成率

### 3. 历史行情采集器集成

- **位置**: `backend_core/data_collectors/tushare/historical.py`
- **说明**: 在数据采集完成后自动调用涨跌幅计算（5 日及扩展 5/10/60 日），无缝集成，不影响原有采集流程。

### 4. 独立计算脚本

- **5 日涨跌幅**: `backend_core/data_collectors/tushare/calculate_five_day_change.py`
  - 支持命令行手动触发：单日期、日期范围、最近 N 天、状态查询
- **扩展涨跌幅**: 通过 `ExtendedChangeCalculator` 编程调用或采集流程自动触发

| `five_day_change_percent` | DECIMAL(8,2) / REAL | 5 日涨跌幅百分比 |
| `ten_day_change_percent` | REAL | 10 日涨跌幅 |
| `sixty_day_change_percent` | REAL | 60 日涨跌幅 |

### 操作日志 (historical_collect_operation_logs)

- `operation_type`: 如 `'five_day_change_calculation'`、扩展涨跌幅计算类型

- `status`: `'success'` | `'partial_success'` | `'error'`
- `affected_rows`、`created_at` 等

## 计算逻辑

### 计算公式

- **5 日涨跌幅** = (当前收盘价 - 5 日前收盘价) / 5 日前收盘价 × 100
- **10 日涨跌幅** = (当前收盘价 - 10 日前收盘价) / 10 日前收盘价 × 100
- **60 日涨跌幅** = (当前收盘价 - 60 日前收盘价) / 60 日前收盘价 × 100

### 计算规则

- **时间定义**: 按交易日（非自然日）
- **数据要求**:
  - 5 日: 至少 6 天历史数据
  - 10 日: 至少 11 天历史数据
  - 60 日: 至少 61 天历史数据
- **精度**: 结果保留 2 位小数
- **异常**: 对无效数据（收盘价为 0 或负数、数据不足）跳过计算；数据库异常回滚事务

### 自动集成流程示例

```python
# 历史行情数据采集完成后自动执行
if success_count > 0:
    try:
        self.logger.info("开始自动计算涨跌幅...")
        target_date = datetime.datetime.strptime(date_str, "%Y%m%d").strftime("%Y-%m-%d")
        calculator = ExtendedChangeCalculator(session)  # 或 FiveDayChangeCalculator
        calc_result = calculator.calculate_for_date(target_date)
        self._log_calculation_result(calc_result)
    except Exception as calc_error:
        self.logger.error(f"自动计算涨跌幅失败: {calc_error}")
        self._log_calculation_error(calc_error)
```

## 使用方法

### 1. 数据库迁移

首次使用扩展涨跌幅（10 日、60 日）前需执行迁移：

```bash

python run_migrate_extended_change_fields.py

# 方法2: 直接运行迁移模块
python -m backend_core.data_collectors.tushare.migrate_extended_change_fields
```

若仅有 5 日字段，可执行：

```sql

```

### 2. 自动计算（推荐）

系统在每日历史行情数据采集完成后会自动计算涨跌幅，无需人工干预。

### 3. 历史行情采集命令

```bash
python -m backend_core.data_collectors.tushare.main --type historical --date 20241201
```

### 4. 手动计算

#### 4.1 5 日涨跌幅命令行

```bash

python backend_core/data_collectors/tushare/calculate_five_day_change.py --mode date --date 2025-01-01

# 计算日期范围
python backend_core/data_collectors/tushare/calculate_five_day_change.py --mode range --start-date 2025-01-01 --end-date 2025-01-31

# 计算最近 30 天
python backend_core/data_collectors/tushare/calculate_five_day_change.py --mode recent --days 30

# 查看计算状态
python backend_core/data_collectors/tushare/calculate_five_day_change.py --mode status --date 2025-01-01
```

#### 4.2 扩展涨跌幅编程接口

```python

```

## 技术实现细节

### 1. 性能优化

- 使用 SQL UPDATE 批量更新，减少数据库交互
- 合理的事务提交频率，避免长时间锁定
- 只计算需要更新的记录，内存友好

### 2. 错误处理

- 数据不足、收盘价无效的股票跳过计算
- 数据库操作异常回滚事务
- 支持部分失败，记录详细错误信息与股票代码

### 3. 日志记录

- 操作日志：操作类型、影响行数、状态
- 错误日志：失败原因、具体股票代码
- 统计信息：完成率、成功/失败数量

```sql
-- 某日涨跌幅数据
SELECT code, name, five_day_change_percent, ten_day_change_percent, sixty_day_change_percent
FROM historical_quotes
WHERE date = '2024-12-01' AND five_day_change_percent IS NOT NULL

-- 5 日计算状态
SELECT

FROM historical_collect_operation_logs
WHERE operation_type = 'five_day_change_calculation'
```

## 注意事项

1. **数据依赖**: 60 日涨跌幅需要至少 61 天历史数据；建议先保证历史数据连续、完整再计算。
2. **计算顺序**: 先完成历史数据采集，再执行或依赖自动计算。
3. **性能**: 全市场大量数据计算可能耗时较长，建议在非高峰期执行。
4. **数据一致性**: 确保历史数据的连续性和完整性，避免缺失交易日导致计算偏差。
