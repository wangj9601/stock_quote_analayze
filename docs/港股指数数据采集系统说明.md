# 港股指数数据采集系统说明

## 系统概述

本系统实现港股指数数据的完整采集、存储与查询，包括：

1. **全量港股指数实时行情采集**：从 akshare 获取数据并写入数据库，前端从数据库读取而非直连 akshare
2. **港股指数基础信息管理**：指数代码、名称等基础信息分表存储
3. **港股指数历史行情归档**：每日休市后自动将当日实时行情转存到历史表，用于分析与回测

## 核心组件

### 1. HKIndexRealtimeCollector（实时行情采集器）

- **位置**：`backend_core/data_collectors/akshare/hk_index_realtime.py`
- **功能**：
  - 从 akshare 获取全量港股指数（不限于 4 个主要指数）
  - 优先使用 `stock_hk_index_spot_em`，失败时切换 `stock_hk_index_daily_sina`
  - 基础信息写入 `hk_index_basic_info`，实时行情按日期写入 `hk_index_realtime_quotes`
  - 使用 ON CONFLICT DO UPDATE 实现 UPSERT，批量提交与事务优化
- **主要指数示例**：HSI（恒生指数）、HSTECH（恒生科技）、HSCI（恒生综合）、HSCEI（恒生中国企业指数）等
- **关键方法**：`collect_realtime_quotes()` — 采集实时行情

### 2. HKIndexHistoricalCollector（历史行情归档）

- **位置**：`backend_core/data_collectors/akshare/hk_index_historical_collector.py`
- **功能**：
  - 从 `hk_index_realtime_quotes` 读取指定日期数据，转存到 `hk_index_historical_quotes`
  - 支持单日与日期范围批量补采
- **关键方法**：
  - `collect_daily_to_historical(trade_date=None)` — 指定日期转存，默认当天
  - `collect_date_range(start_date, end_date)` — 批量采集日期范围

#### 实时 → 历史字段映射

| 实时行情字段 | 历史行情字段 | 说明 |
|------------|------------|------|
| code | code | 指数代码 |
| name | name | 指数名称 |
| trade_date | date | 交易日期 |
| open, high, low | open, high, low | 开高低 |
| price | close | 收盘价 |
| volume, amount | volume, amount | 成交量、成交额 |
| change, pct_chg | change, pct_chg | 涨跌额、涨跌幅 |
| - | collected_source | 固定为 'realtime_quotes' |
| - | collected_date | 采集时间 |

## 数据流程与定时任务

### 数据流程概览

1. **实时采集**：定时任务调用 `HKIndexRealtimeCollector.collect_realtime_quotes()`
2. **数据分类**：基础信息 → `hk_index_basic_info`；实时行情 → `hk_index_realtime_quotes`（按 trade_date）
3. **API 查询**：先查当前日期，无数据则查最新交易日
4. **历史归档**：每日 17:05 将当日实时数据转存到 `hk_index_historical_quotes`

### 日内数据流

```
09:05 → 实时采集 → hk_index_basic_info + hk_index_realtime_quotes
09:35 → 实时采集 → 更新 hk_index_realtime_quotes
...
16:35 → 实时采集 → 最后一次更新
17:05 → 历史归档 → hk_index_realtime_quotes → hk_index_historical_quotes
```

### 定时任务配置

**实时行情采集**

- **任务 ID**：`hk_index_realtime`
- **执行时间**：周一至周五，9–12 点、13–16 点，每小时第 5、35 分（每 30 分钟一次）
- **执行函数**：`collect_hk_index_realtime()`

```python
scheduler.add_job(
    collect_hk_index_realtime,
    'cron',
    day_of_week='mon-fri',
    hour='9-12,13-16',
    minute='5,35',
    id='hk_index_realtime'
)
```

**历史行情归档**

- **任务 ID**：`hk_index_historical`
- **执行时间**：周一至周五 17:05，每日一次
- **执行函数**：`collect_hk_index_historical()`

```python
scheduler.add_job(
    collect_hk_index_historical,
    'cron',
    day_of_week='mon-fri',
    hour=17,
    minute=5,
    id='hk_index_historical'
)
```

### 数据保留策略

- **基础信息表**：永久保留，仅更新
- **实时行情表**：按日期保留，支持历史查询
- **历史行情表**：永久保留，用于长期分析

## API 接口

### GET /api/market/hk-indices

获取港股指数数据（供前端展示）。

- **请求参数**：无
- **数据来源**：从 `hk_index_realtime_quotes` 读取（不直连 akshare）
- **查询逻辑**：优先当前日期，无数据则查最新交易日

## 监控与维护

### 查看采集日志

```sql
-- 最近采集记录
SELECT * FROM hk_index_collect_operation_logs
ORDER BY created_at DESC
LIMIT 20;

-- 失败记录
SELECT * FROM hk_index_collect_operation_logs
WHERE status = 'error'
ORDER BY created_at DESC;

-- 按类型统计成功率
SELECT
    operation_type,
    COUNT(*) AS total,
    SUM(CASE WHEN status = 'success' THEN 1 ELSE 0 END) AS success,
    SUM(CASE WHEN status = 'error' THEN 1 ELSE 0 END) AS failed
FROM hk_index_collect_operation_logs
GROUP BY operation_type;
```

### 数据质量检查

```sql
-- 实时表：各指数交易日数
SELECT code, name, COUNT(DISTINCT trade_date) AS trading_days
FROM hk_index_realtime_quotes
GROUP BY code, name
ORDER BY code;

-- 实时表：最新日期与更新时间
SELECT code, name, MAX(trade_date) AS latest_date, MAX(update_time) AS latest_update
FROM hk_index_realtime_quotes
GROUP BY code, name;

-- 历史表：日期范围与天数
SELECT MIN(date) AS earliest_date, MAX(date) AS latest_date, COUNT(DISTINCT date) AS total_days
FROM hk_index_historical_quotes;

-- 历史表：按指数查询
SELECT * FROM hk_index_historical_quotes
WHERE code = 'HSI'
ORDER BY date DESC
LIMIT 30;
```

## 注意事项

1. **首次使用**：确保数据库表已创建（模型在 `backend_api/models.py`）。
2. **网络依赖**：采集依赖 akshare 接口，建议配置网络代理以提高稳定性。
3. **数据时效**：实时数据每 30 分钟更新；17:05 执行历史归档，依赖当日实时数据已采集完成。
4. **数据依赖**：历史归档依赖实时表有对应日期数据，无数据时归档会返回“未找到”类提示。
5. **同一日数据**：实时表、历史表同一日期的记录会更新（UPSERT），不会重复插入。
6. **错误处理**：采集失败会写入操作日志，支持自动重试与多数据源降级，不影响其他定时任务。
