## 1. 前端认证与 API 调用

### 1.1 认证体系概览

- **页面级认证**：页面加载时检查登录状态；未登录跳转登录页；Token 失效后清除本地存储并跳转。
- **全局工具**：`authFetch(url, options)`（带 token 的 fetch，自动处理 401）、`CommonUtils.auth.checkLogin()`、`getUserInfo()`、`logout()`。
- **按钮级认证**：需认证的按钮执行前应做登录检查，或使用 `CommonUtils.requireAuth` / `requireAuthAsync` 包装。

### 1.2 authFetch 与 401 处理

- **authFetch**：自动添加 `Authorization: Bearer ${token}`；检测 401 后清除本地存储并跳转登录页；适合所有需认证接口。
- **smartFetch**：按 URL 判断是否需认证；需认证的端点内部用 `authFetch`，公开端点用普通 `fetch`。
- **401 处理流程**：清除 `access_token`、`userInfo`、`token`；Toast「登录已过期，请重新登录」；跳转 `login.html`（非登录页时）。

### 1.3 需要认证的 API 示例

- 自选股：`/api/watchlist`、`/api/watchlist/groups/*`
- 历史行情与计算：`/api/stock/history`、`/api/stock/history/calculate_*_day_change`、`/api/trading_notes/*`
- 分析与用户：`/api/analysis/`、`/api/user/`、`/api/admin/`

### 1.4 按钮功能认证

- **方法一**：在函数内先检查 `CommonUtils.auth.getUserInfo()`，无则提示「请先登录」并 return。
- **方法二**：使用 `CommonUtils.requireAuth(fn)` 或 `requireAuthAsync(async fn)` 包装，未登录时自动拦截。

### 1.5 最佳实践

- 需认证的接口统一使用 `authFetch`；不确定时用 `smartFetch`。
- 响应用 `response.ok` 或 `response.status` 判断成功/失败；依赖 `authFetch` 统一处理 401，业务中不重复写 401 逻辑。
- 测试登录失效：控制台执行 `CommonUtils.testApiLoginExpiry()`；或清除 localStorage 后调用 authFetch 验证跳转。

行情频道股票列表页实现自选股添加/删除，利旧后端自选股 API，不修改其他行情逻辑。

## 3. 历史行情功能

### 3.1 功能概述

- **数据展示**：按股票、日期范围查询、分页；支持不选股票时展示全部历史行情。
- **扩展字段**：累计升跌%、5/10/30/60 天升跌%、备注（与 trading_notes 关联）。
- **交易备注**：按股票与交易日维护策略类型、风险等级、备注内容；行内编辑开盘/收盘/最高/最低/成交量/成交额/换手率/备注。
- **多周期涨跌计算**：在历史行情页选择日期范围后，一键计算 5/10/30/60 天涨跌% 并写回数据库。

### 3.2 数据层与表结构

- **historical_quotes**：新增 `cumulative_change_percent`、`five_day_change_percent`、`ten_day_change_percent`、`thirty_day_change_percent`、`sixty_day_change_percent`、`remarks` 等（类型以迁移为准）。
- **trading_notes**：stock_code、trade_date、notes、strategy_type、risk_level 等；唯一约束 (stock_code, trade_date)。
- **主键与 ON CONFLICT**：`historical_quotes` 需主键 (code, date)，否则 PostgreSQL 的 ON CONFLICT 会失败；迁移/修复脚本如 `fix_historical_quotes_table.py` 或 `database/fix_historical_quotes_table.sql`。

### 3.3 接口层

- **历史行情**：GET `/api/stock/history` 或 GET `/history`（code 可选、分页、start_date、end_date、include_notes）；PUT 按 code/date 更新单条（行内编辑）；支持带备注的 CSV 导出。
- **交易备注**：POST/GET/PUT/DELETE `/api/trading_notes/*`；GET `.../with_quotes` 历史行情含备注；POST `.../calculate_fields` 计算派生字段；GET strategy_types 等。
- **股票列表**：GET `/api/quotes/stocks/list` 或 `/stocks/list` 供历史行情页下拉。

### 3.4 默认展示与“必须选股票”修复

- 后端：GET history 将 `code` 改为可选；code 为空时查询所有股票（分页、日期筛选）；code 有值时仅查该股票。
- 前端：去掉“股票代码为空则直接 return”；onMounted 时自动 `fetchHistoricalData()`，使页面打开即显示最近历史数据。

### 3.5 5 天升跌计算（历史行情页）

- 接口：POST `/api/stock/history/calculate_five_day_change`，body：stock_code、start_date、end_date；响应含 updated_count、total_records 等。
- 计算规则：5 个交易日（非自然日）；需“开始日期前 5 个工作日”的数据，后端扩展查询范围，仅更新用户指定日期范围内的记录（详见第 4 节）。
- 前端：工具栏「计算 5 天升跌」按钮；选择股票与日期后调用 API；计算中禁用按钮并刷新列表。

### 3.6 相关文件

- 接口：backend_api/stock/history_api.py、backend_api/quotes_routes.py、backend_api/trading_notes_routes.py
- 前端：admin/src/services/quotes.service.ts、admin/src/views/QuotesView.vue
- 表扩展/修复：database/extend_historical_quotes_table.*、fix_historical_quotes_table.*

## 4. 涨跌幅计算（多周期）

### 4.1 概述与周期

系统支持 **5 日、10 日、30 日、60 日** 涨跌幅的自动与手动计算，均按**交易日**（非自然日）计算。

| 周期 | 字段名 | 最少数据 |
|------|--------|----------|
| 5 日 | five_day_change_percent | 6 天 |
| 10 日 | ten_day_change_percent | 11 天 |
| 30 日 | thirty_day_change_percent | 31 天 |
| 60 日 | sixty_day_change_percent | 61 天 |

公式统一：**N 日涨跌幅% = (当前收盘价 - N 个交易日前收盘价) / N 个交易日前收盘价 × 100**，精度保留 2 位小数。

### 4.2 核心组件与入口

- **5 日**：`FiveDayChangeCalculator`（backend_core/data_collectors/tushare/five_day_change_calculator.py）；命令行 `calculate_five_day_change.py`（--mode date/range/recent/status）。
- **扩展 5/10/60 日**：`ExtendedChangeCalculator`（extended_change_calculator.py）；历史采集完成后自动调用。
- **30 日**：`ThirtyDayChangeCalculator`（thirty_day_change_calculator.py）；采集流程中在扩展涨跌幅之后串联执行；API + CLI 支持。
- **历史采集集成**：`backend_core/data_collectors/tushare/historical.py` 在采集成功后自动执行涨跌幅计算（5 日及扩展/30 日），并写操作日志。

### 4.3 数据库与日志

- **historical_quotes**：字段 five_day_change_percent、ten_day_change_percent、thirty_day_change_percent、sixty_day_change_percent（类型 DECIMAL/REAL 以迁移为准）。
- **historical_collect_operation_logs**：operation_type 如 five_day_change_calculation、thirty_day_change_calculation 等；operation_desc、status、affected_rows。

### 4.4 后端 API（历史行情页触发）

- POST `/api/stock/history/calculate_five_day_change`、`calculate_ten_day_change`、`calculate_thirty_day_change`、`calculate_sixty_day_change`。
- 请求体含 stock_code、start_date、end_date；30 日等支持 extended_end_date（向前多取 30 个工作日）。
- **扩展查询范围**：计算某日 N 日涨跌需该日前 N 个交易日数据；后端将查询起始日期向前扩展 N 个工作日，只对用户选择的日期范围内记录做 UPDATE。

### 4.5 前端（历史行情页）

- 按钮：「计算5天升跌」「计算10天涨跌」「计算30天涨跌」「计算60天涨跌」；30 天时结束日期自动延长 30 个工作日并传 extended_end_date。
- 表格列：5天涨跌%、10天涨跌%、30天涨跌%、60天涨跌%；涨跌颜色一致（红涨绿跌）。60 天功能中曾隐藏「最高」「最低」列以简化界面。

### 4.6 手动计算与迁移

- **命令行**：  
  `python backend_core/data_collectors/tushare/calculate_five_day_change.py --mode date --date 2025-01-01`  
  `python .../calculate_thirty_day_change.py --mode date --date 2025-03-31` 等。
- **扩展字段迁移**：`python run_migrate_extended_change_fields.py` 或 `python -m backend_core.data_collectors.tushare.migrate_extended_change_fields`（含 30 日字段检测与新增）。

### 4.7 注意事项

- 最后几天为空：确认已实现“扩展查询范围 + 仅更新指定范围”；避免“仅更新 NULL/0”导致负值不更新。
- 数据依赖：60 日需至少 61 天历史数据；建议历史数据连续完整后再计算。

## 5. 新闻与资讯

### 5.1 首页市场资讯

- **接口**：GET `/api/news/homepage?limit=3`，从 `stock_news` 按 publish_time 倒序取最新条；默认 limit=3。
- **返回字段**：id、title、summary、publish_time、source、read_count（若表有）。
- **前端**：请求 `/api/news/homepage`；展示标题、摘要、时间、来源；「更多」链到资讯频道；可做降级或空状态。

### 5.2 资讯频道 API

- GET `/api/news/categories`：分类列表（无 news_categories 表时返回默认分类）。
- GET `/api/news/list`：列表与分页，参数 category_id、page、page_size、keyword；返回 total 与列表。
- GET `/api/news/hot`：热门资讯，limit 控制条数。
- GET `/api/news/detail/{news_id}`：详情。
- GET `/api/news/statistics`：统计信息。

### 5.3 兼容与修复

- **read_count 等可选字段**：若 `stock_news` 无 read_count/is_hot/tags 等列，应在查询前检测列是否存在或使用动态 SQL，避免 500。
- **详情**：注意 SQL 注入与 XSS（content 富文本需过滤或信任服务端转义）。
- **错误**：统一返回 success、message，并记日志。

### 5.4 前端加载与分页

- 列表用 `/api/news/list`，传 page、page_size、category_id、keyword；切换分类/关键词时 page 置 1。
- 分页条根据 total 与 page_size 计算总页数；「加载更多」为追加 page+1 结果并去重。
- 涉及文件：backend_api/news_channel_routes.py、frontend/js/home.js。

## 7. 股票详情与展示优化

### 7.1 市盈率数据获取（PE_RATIO_DATA_SOLUTION）

- **问题**：详情页市盈率显示「-」；原接口 `stock_bid_ask_em` 不含市盈率。
- **方案**：`get_realtime_quote_by_code` 改为**数据库优先**：优先从 `stock_realtime_quote` 取 pe_dynamic；若无则从 akshare `stock_zh_a_spot_em` 获取。
- **实现位置**：backend_api/stock/stock_manage.py；错误处理与降级，保持兼容。
- **测试**：test/test_pe_ratio_api.py、test_db_pe_ratio.py 等；验证详情页显示数值与响应速度。

### 7.2 K 线图初始显示范围（KLINE_DISPLAY_OPTIMIZATION）

- **问题**：K 线从 2008 年至今全部显示，过于密集。
- **原因**：数据加载后已设置「最近 250 根 K 线」（约一年），但后续「数据量 > 200」分支中又设置 dataZoom start=50%，覆盖为约 50% 历史数据。
- **修改**：删除「数据量 > 200」时覆盖 dataZoom 的代码块，保持初始为最近 250 根 K 线。
- **文件**：frontend/js/stock.js、frontend/js/stock_hk.js。
- **策略**：≤30 根全显；31–80 根全显；81–200 根显示最近 100 根；>200 根显示最近 250 根（约一年）。

## 8. 港股数据采集

- **定时**：实时采集周一至周五 9–12、13–16 点每 30 分钟；历史归档周一至周五 17:05。
- **代码**：backend_core/data_collectors/akshare/hk_index_realtime.py、hk_index_historical_collector.py；backend_api/market_routes.py；定时任务在 backend_core/data_collectors/main.py。

## 9. 周线数据系统

本节为 **A 股/港股周线数据** 的设计与使用摘要，原详见《weekly_data.md》。周线由日线聚合生成，不依赖外部周线 API。

### 9.1 概述与数据流

- **来源**：日线表 historical_quotes（A 股）、historical_quotes_hk（港股）→ WeeklyDataGenerator / HKWeeklyDataGenerator（resample + 指标）→ weekly_quotes / hk_weekly_quotes → API 与前端 K 线。
- **特性**：以周五为周结束日（resample('W-FRI')）；开盘=周内首日开盘，收盘=末日收盘，最高/最低=周内极值，成交量/额=求和；涨跌幅=(本周收-上周收)/上周收×100；INSERT ... ON CONFLICT (code, date) DO UPDATE。

### 9.2 快速开始与命令

- **环境**：Python 3.8+、PostgreSQL、pandas；日线表有数据；A 股股票列表来自 stock_basic_info。
- **测试**：`python backend_core/data_collectors/akshare/weekly_collector.py 2025-01-01 2025-11-30 --test`（前 5 只）。
- **全量/指定范围**：同上命令去掉 --test；可加 `--stocks 000001 600000`。港股：hk_weekly_collector.py，表 hk_weekly_quotes。
- **当前周更新**：定时任务工作日 A 股 16:25、港股 17:03；手动触发见下方编程示例。

### 9.3 定时任务与 API

- **定时**：backend_core/data_collectors/main.py 中 generate_weekly_data()、generate_hk_weekly_data()，内部 generate_current_week_data()。
- **K 线 API**：GET /api/stock/kline_hist?code=xxx&period=weekly&start_date=&end_date=；优先查 weekly_quotes，无则日线 resample 返回。位置：backend_api/stock/stock_manage.py。

## 11. PVFRS 量价频共振策略与回测系统

本节整合 PVFARS 策略说明、PVFRS 回测系统设计、回测表结构与报告列表修复，供策略理解与运维参考。

### 11.1 概述与策略关系

- **PVFRS**：量价频三维共振策略及回测系统。
- **PVFARS**：在三维共振基础上增加**幅度（Amplitude）**等条件。回测与前端「PVFRS」涵盖上述逻辑；指标与信号以 PVFARS 增强版为准。

### 11.2 PVFARS 策略要点

- **价格维度**：宏观位移 Δ、即时强度、幅度与比例；趋势持续性、波动率&lt;15%、乖离率等；有效条件：Δ&gt;0 且 d₂₀&gt;d，趋势持续，波动率&lt;15%。
- **频率维度**：Z（上涨天数）、F（下跌天数）；买点权重 F&gt;Z；虚假繁荣检测、最近 10 天上涨≥6 天等。
- **成交量维度**：20 日均量 m、效率比 m₂₀/m；量价共振、强资金支撑、连续放量、低成色过滤。
- **三维共振与信号**：价格有效 AND 频率有效 AND 成交量有效；买点排除与共振强度、信号强度 0–1；建议等级 BUY/HOLD/WAIT。

### 11.3 回测系统实现与数据流

- **指标与表**：指标存于 `mean_frequency_resonance_indicators`（含 macro_displacement_delta、instant_deviation、rising_days_z、falling_days_f、efficiency_m20_minus_m、ma20_d、mavol20_m、bias）；行情来自 HistoricalQuotes / HistoricalQuotesHK。
- **交易规则**：买入需宏观位移&gt;0、即时偏离&gt;0、Z&gt;F、效率&gt;0，及 bias、相对位移比、连续满足天数等；卖出为趋势反转或价涨量缩背离（≥2 条）；风控：止损 -10%、止盈 +20%、最大持有 30 天、最大仓位 10%。
- **代码目录**：`backend_core/strategies/`（pvfrs_strategy.py、pvfrs_data_loader.py、pvfrs_performance_analyzer.py、pvfrs_backtest_runner.py、pvfrs_config.json）。流程：runner → 配置 → DataLoader 读指标与行情 → 合并 → Strategy 信号 → BacktestEngine 逐日回放 → 报告。

### 11.4 配置与运行

- **pvfrs_config.json**：strategy_params（买卖阈值、连续天数、风控）、backtest_config（如 initial_capital）、optimization_config（可选）。
- **单股回测**：`python backend_core/strategies/pvfrs_backtest_runner.py --mode single --code 688256 --market CN --start-date 2023-01-01 --end-date 2025-12-31 --params-file backend_core/strategies/pvfrs_config.json`
- **批量/优化**：`--mode batch` 或 `--mode optimize`，配合 `--output` 等。

### 11.5 回测数据库表

- **pvfrs_backtest_tasks**：task_id、mode、stock_codes、market、start_date/end_date、initial_capital、status、progress、current_step、error_message、created_at、completed_at。
- **pvfrs_backtest_results**：task_id、stock_code、market、回测日期与区间、初始/最终资金、总收益与年化、max_drawdown、sharpe_ratio、win_rate、profit_factor、total_trades、avg_holding_period。
- **pvfrs_trade_records**：result_id、入场/出场日期与价格、pnl、pnl_percent、exit_reason。
- **pvfrs_equity_curves**：result_id、curve_date、equity。关系：tasks(1)→results(N)→trade_records、equity_curves。建表脚本：`backend_api/create_pvfrs_tables.py`；验证：`backend_api/verify_pvfrs_tables.py`。

### 11.6 报告列表修复与验证

- **问题**：报告与分析页列表不显示。
- **处理**：在 `backend_api/admin/pvfrs_admin_routes.py` 的 `list_reports` 中改为**直接查库** `PVFRSBacktestResultEnhanced`，支持 startDate/endDate 过滤、分页；Decimal/None 用 safe_float、safe_percent；返回字段与前端约定一致（totalReturn、sharpeRatio、winRate、maxDrawdown、createdAt、stockCode、taskId 等）。
- **验证**：管理端 → PVFRS 策略管理 → 报告与分析；检查列表、分页、日期过滤、详情与下载。需存在 `pvfrs_backtest_results_enhanced` 表及数据。
