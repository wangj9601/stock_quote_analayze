# 历史行情功能说明与问题修复

本文档整合历史行情相关的功能扩展、接口补全、显示修复、表结构修复及 5 天升跌计算功能的说明与修复记录。

---

## 一、功能概述

历史行情功能覆盖：

- **数据展示**：按股票、日期范围查询，分页；支持“不选股票”时展示全部历史行情。
- **扩展字段**：累计升跌%、5 天升跌%、备注（与 `trading_notes` 关联）。
- **交易备注**：按股票与交易日维护策略类型、风险等级、备注内容。
- **行内编辑**：修改开盘价、收盘价、最高价、最低价、成交量、成交额、换手率、备注等。
- **5 天升跌计算**：在历史行情页选择日期范围后，一键计算并更新 5 天升跌%。
- **数据格式化**：价格两位小数、涨跌颜色、成交量/成交额单位、换手率百分比。

## 二、功能扩展（表结构与接口）

### 2.1 数据层扩展

**表 `historical_quotes` 新增字段示例**：

- `cumulative_change_percent` (DECIMAL(8,2)) — 累计升跌%
- `five_day_change_percent` (DECIMAL(8,2)) — 5 天升跌%
- `remarks` (TEXT) — 备注

**表 `trading_notes`（交易备注）**：

- 字段示例：`stock_code`, `trade_date`, `notes`, `strategy_type`, `risk_level`, `created_at`, `updated_at`, `created_by`
- 唯一约束：`(stock_code, trade_date)`

**扩展脚本**：如 `database/extend_historical_quotes_table.py`、`extend_historical_quotes_table.sql`；视项目保留视图、索引、触发器。

### 2.2 接口层

**历史行情**（`backend_api/stock/history_api.py` 或 `quotes_routes.py` 等）：

- 支持新字段与 `include_notes` 参数；支持带备注的 CSV 导出。

**交易备注**（`backend_api/trading_notes_routes.py`）：

- `POST /api/trading_notes/` — 创建
- `GET /api/trading_notes/{stock_code}` — 按股票查询
- `PUT /api/trading_notes/{note_id}` — 更新
- `DELETE /api/trading_notes/{note_id}` — 删除
- `GET /api/trading_notes/{stock_code}/with_quotes` — 历史行情含备注
- `POST /api/trading_notes/{stock_code}/calculate_fields` — 计算派生字段
- `GET /api/trading_notes/strategy_types` — 策略类型/风险等级选项

**前端**：历史行情页增加累计升跌%、5 天升跌%、备注列；备注弹窗（策略类型：买入/卖出/观察/持有/加仓/减仓/止损/止盈；风险等级：低/中/高）。

## 三、表结构修复（主键与 ON CONFLICT）

### 3.1 问题

生产环境同步历史数据时报错：`ON CONFLICT (code, date) DO UPDATE` 失败。原因多为：

- `historical_quotes` 缺少主键约束，导致 PostgreSQL 无法执行 ON CONFLICT。
- 从 SQLite 迁移到 PostgreSQL 时约束/索引未正确创建。

### 3.2 修复方案

1. **主键**：为 `historical_quotes` 添加主键 `(code, date)`。
2. **去重**：修复前删除重复数据（如有）。
3. **索引**：例如 `idx_historical_quotes_code`、`idx_historical_quotes_date`、`idx_historical_quotes_collected_date`。
4. **执行**：使用项目提供的 Python 脚本（如 `fix_historical_quotes_table.py`）或 SQL 脚本（如 `database/fix_historical_quotes_table.sql`）。

### 3.3 验证

```sql
-- 约束
SELECT conname, contype, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid = 'historical_quotes'::regclass;

-- 索引
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'historical_quotes';
```

执行修复前建议备份数据库，低峰期执行；修复后测试 INSERT ... ON CONFLICT 插入/更新。

## 四、接口缺失与 404 修复

### 4.1 问题

管理端历史行情标签页请求 `/api/quotes/stocks/list`、`/api/quotes/history` 等返回 404，无法加载股票列表与历史数据。

### 4.2 解决方案

在 `backend_api/quotes_routes.py`（或等价路由文件）中补全接口：

- **GET `/stocks/list`**：从 `stock_basic_info` 等表获取股票列表（code, name），供历史行情页下拉使用。
- **GET `/history`**：查询历史行情，参数如 `code`（可选）、`page`、`size`、`start_date`、`end_date`、`include_notes`。
- **PUT `/history/{code}/{date}`**：按股票代码与日期更新单条历史行情（行内编辑保存）。

并确保在 `main.py` 中注册 quotes 相关路由。

### 4.3 前端

- `admin/src/services/quotes.service.ts`：实现 `getStockList()`、`getHistoricalQuotes()`、`updateHistoricalQuote()` 及对应类型。
- `admin/src/views/QuotesView.vue`：历史行情数据标签、表格、筛选、行内编辑、调用上述服务。

## 五、默认展示与“必须选股票”修复

### 5.1 问题

历史行情页必须选择股票才显示数据，否则为“No Data”，体验不佳。

### 5.2 修改要点

**后端**（如 `quotes_routes.py`）：

- **GET `/history`**：将 `code` 改为可选（如 `code: Optional[str] = Query(None, ...)`）。  
  - `code` 为空：查询所有股票的历史行情（可分页、按日期筛选）。  
  - `code` 有值：仅查询该股票。
- **GET `/stocks/list`**：若曾用 `DISTINCT` 导致问题，可改为直接查 `stock_basic_info`（以实际需求为准）。

**前端**：

- `quotes.service.ts`：`getHistoricalQuotes` 仅在 `code` 有值时才传 `code` 参数。
- `QuotesView.vue`：去掉“股票代码为空则直接 return”的逻辑；在 `onMounted` 中自动调用 `fetchHistoricalData()`，使页面加载即展示最近历史数据（可不选股票）。

效果：页面打开即可看到历史行情列表；选股票后筛选为单只；日期、备注选项与分页照常可用。

## 六、5 天升跌计算功能（历史行情页）

### 6.1 功能

在历史行情页选择股票与日期范围后，点击“计算 5 天升跌”，后端计算该范围内 5 天升跌% 并写回 `historical_quotes.five_day_change_percent`，页面刷新后显示最新结果。

### 6.2 接口

- **POST** `/api/stock/history/calculate_five_day_change`（或项目内等价路径）
- **请求体**：`{ "stock_code": "000001", "start_date": "2024-01-01", "end_date": "2024-01-31" }`
- **响应**：包含 `message`、`updated_count`、`total_records` 等。

### 6.3 计算规则

- 公式：`5天升跌% = (当前收盘价 - 5个交易日前收盘价) / 5个交易日前收盘价 × 100`
- 5 个交易日（非自然日）；从第 6 个交易日开始可算；至少 6 天数据；结果保留 2 位小数。
- 注意：若仅更新“5天升跌% 为 NULL 或 0”的记录，会导致已有值（如负值）不更新；若需范围内全量一致，应改为对范围内日期全部重算并更新。另，计算最后几天时需“开始日期前 5 个交易日”的数据，后端应扩展查询范围（详见项目内《五日涨跌幅计算功能说明与实现》）。

### 6.4 前端

- 工具栏“计算 5 天升跌”按钮；取当前选择的股票与日期范围调用上述 API；计算中禁用按钮、显示状态；完成后刷新列表。

## 七、使用方式概要

1. **启动**：启动后端 API 与管理端前端（如 `python start_backend_api.py`，`cd admin && npm run dev`）。
2. **访问**：打开管理端（如 `http://localhost:3000/admin`）→ 行情数据 → 历史行情数据标签。
3. **查看**：页面加载后即可看到历史数据（可不选股票）；可选股票、日期范围、是否包含备注后点击刷新。
4. **编辑**：行内编辑后保存，调用 `PUT /history/{code}/{date}`。
5. **5 天升跌**：选择股票与日期范围 → 点击“计算 5 天升跌” → 等待完成 → 刷新查看。
6. **备注**：勾选“包含交易备注”，在备注列或弹窗中编辑策略类型、风险等级与内容。

## 九、注意事项

- **表修复**：生产执行主键/索引修复前备份，低峰期执行，修复后验证 ON CONFLICT 与采集任务。
- **数据质量**：行内编辑需做价格合理性校验；建议重要修改前备份或留审计日志。
- **5 天升跌**：日期范围末尾几天依赖“开始日期前 5 个交易日”数据，后端需扩展查询范围并只更新用户选择范围内的记录。
- **并发**：多用户同时编辑同一条历史记录时，需考虑并发与覆盖策略。
