# 公司内部用户：企业微信 + 邮件推送配置指南

适用于仅面向**公司内部用户**的股票报告推送，推荐只启用**企业微信**与**邮件**两个渠道，不涉及个人微信公众号。

---

## 1. 方案说明

| 项目 | 说明 |
|------|------|
| 推送渠道 | 企业微信（应用消息）、邮件 |
| 接收方式 | 企业微信 App 收应用消息；邮箱收邮件 |
| 适用对象 | 公司内部用户（企业微信成员） |
| 不涉及 | 个人微信公众号、订阅消息、个人微信号直接推送 |

系统已集成企业微信发送能力：先发一条文本摘要，再发 CSV 报告文件。用户需安装企业微信并加入企业，在应用可见范围内的成员即可收到。

---

## 2. 企业微信后台配置

### 2.1 创建自建应用

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/)。
2. **应用管理** → **应用** → **自建** → **创建应用**。
3. 填写应用名称（如「股票报告」）、选择可见范围（需包含要接收推送的成员或部门）。
4. 创建完成后记录：
   - **AgentId**（应用详情页）
   - 企业 **CorpID**（我的企业 → 企业信息）
   - 该应用的 **Secret**（应用详情页）

### 2.2 配置可信 IP（必做）

企业微信要求调用发消息接口的服务器 IP 加入白名单，否则会报错。

1. **应用管理** → 进入该自建应用 → **企业微信授权** 或 **接收消息** 等设置所在页。
2. 找到 **可信 IP** / **IP 白名单**，添加运行本系统及调度器的服务器公网 IP（可多个）。

---

## 3. 本系统环境变量

在运行**后端 API** 和 **推送调度器**（`start_scheduler.py`）的机器上配置环境变量：

```bash
# 企业微信（必填，否则微信渠道不可用）
WECHAT_CORP_ID=你的企业ID
WECHAT_CORP_SECRET=自建应用的Secret
WECHAT_AGENT_ID=自建应用的AgentId
```

- 可从 `.env`、`.env.local` 或系统环境注入，保证执行 `start_scheduler.py` 的进程能读到上述三个变量。
- 邮件相关配置（SMTP 等）若已按现有邮件推送文档配置即可，此处不重复。

---

## 4. 用户侧：企业微信身份与推送配置

### 4.1 企业微信 userid 与 `wechat_openid` 字段

- 本系统**微信通道**实际调用的是**企业微信「发送应用消息」接口**，接收人参数为**企业微信的 userid**（成员账号，如 `zhangsan`），不是公众号 OpenID。
- 用户表中用 **`wechat_openid`** 存储该标识：用于企业微信时，请填**企业微信成员 userid**；`wechat_type` 建议设为 `enterprise`。

获取成员 userid：

- 管理后台：**通讯录** → 点击成员 → **账号**（即 userid）。
- 或通过 [通讯录 API](https://developer.work.weixin.qq.com/document/path/90196) 拉取成员列表获取。

### 4.2 为用户配置推送

每个需要接收报告的用户需满足：

1. **用户表 `users`**
   - `wechat_openid`：填该成员在企业微信中的 **userid**（企业微信通道必填）。
   - `wechat_type`：填 `enterprise`。
   - `email`：若启用邮件通道，必填且有效。

2. **推送配置表 `user_push_configs`**
   - 存在该 `user_id` 的配置且 `enabled = true`。
   - `channels`：只启用企业微信与邮件时，设为 `["wechat", "email"]` 或 `["wechat"]` / `["email"]`。
   - `push_times`：推送时间点，如 `["09:30", "16:00"]`（与调度器从该表读取的时间一致）。
   - `report_type`：如 `gms_daily`、`summary`、`detailed` 等，按需设置。
   - 若按自选股推送，配置好 `stock_codes` 或依赖系统从自选股拉取逻辑。

管理端或现有「报告管理」-「报告推送配置」等页面中，为对应用户创建/编辑推送配置时，渠道选择 **wechat / email** 即可。

### 4.3 用户绑定微信接口（可选）

若通过 API 由用户自行“绑定微信”，需保证传入的为**企业微信 userid**，并写库到 `wechat_openid`，`wechat_type` 设为 `enterprise`。  
当前接口见 `backend_api/push_routes.py` 中绑定/解绑逻辑；管理端若支持编辑用户，也可在此维护 `wechat_openid`（企业微信 userid）。

## 5. 推送调度器与推送时间

- 定时任务由 **PushScheduler** 执行，入口为项目根目录：

  ```bash
  python start_scheduler.py
  ```

- 调度器会从 **`user_push_configs`** 中读取所有启用配置的 **`push_times`** 去重后，在对应时间点触发批量推送。
- 每个时间点会查询该时间需要推送的用户，逐用户生成报告并按配置的 `channels` 发送（企业微信 + 邮件）。  
- 默认单线程执行，避免 DB Session 并发问题；如需调整见 `PushService.execute_scheduled_push` 的 `max_workers` 说明。

## 6. 仅启用企业微信 + 邮件的检查清单

- [ ] 企业微信自建应用已创建，CorpID、Secret、AgentId 已获取。
- [ ] 企业微信后台已配置**可信 IP**（运行本系统与调度器的服务器 IP）。
- [ ] 环境变量 `WECHAT_CORP_ID`、`WECHAT_CORP_SECRET`、`WECHAT_AGENT_ID` 已配置且生效。
- [ ] 用户为**企业微信成员**，且在自建应用**可见范围**内。
- [ ] 用户表中 `wechat_openid` 为该成员的企业微信 **userid**，`wechat_type` 为 `enterprise`（若走微信通道）。
- [ ] `user_push_configs` 中该用户已启用，`channels` 含 `wechat` 和/或 `email`，`push_times` 与期望时间一致。
- [ ] 调度器已启动（`python start_scheduler.py`），且无报错（如 token 获取失败、invaliduser 等可在日志中排查）。

---

## 7. 常见问题

- **收不到企业微信消息**  
  检查：可信 IP 是否包含发送请求的服务器；成员是否在应用可见范围内；`wechat_openid` 是否为该成员的企业微信 userid；环境变量是否在运行调度器的进程中生效。

- **报错 invaliduser**  
  表示接收人不是合法企业微信 userid，或不在应用可见范围内。请用管理后台通讯录中的「账号」核对并修正 `wechat_openid`。

- **只走企业微信、不走邮件**  
  在 `user_push_configs.channels` 中只保留 `["wechat"]`，并确保用户 `wechat_openid` 已填。

- **公司内部用户不要个人微信推送**  
  本方案不接入微信公众号，仅使用企业微信应用消息 + 邮件，不涉及个人微信直接推送。

## 8. 相关代码与配置位置

| 说明 | 路径/位置 |
|------|------------|
| 企业微信配置 | `backend_core/wechat/wechat_config.py`（读环境变量） |
| 企业微信发送 | `backend_core/wechat/wechat_service.py`（文本 + 文件） |
| 推送服务与渠道选择 | `backend_api/services/push_service.py`（`_send_via_wechat`、channels 判断） |
| 用户模型 | `backend_api/models.py`（User.wechat_openid, wechat_type） |
| 推送配置 | `user_push_configs` 表，ConfigService |
| 调度入口 | 项目根目录 `start_scheduler.py` |

按上述步骤配置后，公司内部用户即可仅通过**企业微信 + 邮件**接收股票报告，无需也不使用个人微信公众号或个人微信号直接推送。
