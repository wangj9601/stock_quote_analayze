# 新闻与资讯功能说明与实现

本文档整合首页市场资讯、资讯频道 API、新闻接口修复及加载与分页相关说明（依据现有文档与代码整理）。

---

## 一、首页市场资讯功能

### 1.1 概述

在首页市场概览中提供「市场资讯」模块，展示最新若干条市场资讯，并支持跳转到完整资讯频道。

### 1.2 接口

**GET** `/api/news/homepage?limit=3`

- 从 `stock_news` 表按发布时间倒序取最新记录。
- 默认 `limit=3`，可传参修改条数。
- 返回字段示例：id、title、summary、publish_time、source、read_count（若表中有）。

**响应示例：**

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "title": "市场调整后迎来反弹机会",
      "summary": "专家认为当前市场估值合理,优质股票值得关注",
      "publish_time": "2025-09-08 20:16:02",
      "source": "财经日报",
      "read_count": 12000
    }
  ]
}
```

### 1.3 前端实现要点

- **调用路径**：前端请求 `/api/news/homepage`（或带 `limit`），不要用错误或旧路径。
- **时间格式**：可按需只显示时分秒，例如 `toLocaleTimeString('zh-CN', { hour: '2-digit', minute: '2-digit', second: '2-digit' })`。
- **展示**：标题、摘要、时间、来源；「更多 >」链接到资讯频道页。
- **降级**：可保留模拟数据或空状态，在接口失败时使用。

### 1.4 涉及文件

- 后端：`backend_api/news_channel_routes.py`（如 `get_homepage_news`）。
- 前端：`frontend/js/home.js`（首页市场资讯区域的数据请求与渲染）。

### 1.5 数据库查询逻辑

- 表：`stock_news`。
- 排序：`ORDER BY publish_time DESC`。
- 无 `summary` 时可从 `content` 截断生成摘要；`read_count` 等字段按表结构可选返回。

## 二、资讯频道 API 与列表分页

### 2.1 接口一览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/news/categories` | GET | 资讯分类列表（若存在 `news_categories` 表则查表，否则返回默认分类） |
| `/api/news/list` | GET | 资讯列表，支持分类、关键词、分页 |
| `/api/news/homepage` | GET | 首页最新 N 条（见第一节） |
| `/api/news/hot` | GET | 热门资讯，`limit` 控制条数 |
| `/api/news/detail/{news_id}` | GET | 资讯详情 |
| `/api/news/statistics` | GET | 资讯统计信息 |

### 2.2 列表与分页（GET /api/news/list）

**常用参数：**

- `category_id`：分类 ID，不传或 1 表示「全部」。
- `page`：页码，从 1 开始。
- `page_size`：每页条数，如 20。
- `keyword`：搜索关键词，匹配标题或正文。

**逻辑要点：**

- 分页：`offset = (page - 1) * page_size`，SQL 使用 `OFFSET :offset LIMIT :limit`。
- 返回列表中除基础字段外，按表结构可选返回 `read_count`、`is_hot`、`tags`、`image_url`、`category_id` 等（通过表结构检测兼容未建字段的环境）。
- 同时返回 `total` 便于前端分页组件计算总页数。

### 2.3 分类与表结构兼容

- 若 `news_categories` 表不存在，接口可返回内置默认分类（如全部、市场动态、政策解读等），避免 500。
- `stock_news` 若缺少 `read_count`、`category_id` 等列，应在查询前检测列是否存在或使用动态 SQL，避免因单列缺失导致整表查询失败。

## 三、新闻 API 常见修复与兼容

### 3.1 read_count 等可选字段

- 问题：直接 `SELECT read_count` 时，若表中无该列会报错。
- 做法：启动时或首次请求时检测 `stock_news` 表结构（如 `information_schema.columns`），仅当存在 `read_count` 时才加入 SELECT 与返回结果；同理可处理 `is_hot`、`tags`、`image_url`、`category_id`。

### 3.2 资讯详情与内容安全

- 详情接口根据 `news_id` 查询单条；注意 SQL 注入与权限（若后续做用户态）。
- 返回的 `content` 若为富文本，前端需做 XSS 过滤或仅信任服务端转义后的内容。

### 3.3 错误与日志

- 接口异常时返回统一格式（如 `success: false, message: "错误原因"`），并记录日志，便于排查「新闻 API 不返回数据」或 500 问题。

## 四、新闻加载与分页（前端）

### 4.1 列表页加载

- 使用 `/api/news/list`，传入 `page`、`page_size`、`category_id`、`keyword`（可选）。
- 首次进入或切换分类/关键词时，将 `page` 置为 1 再请求。
- 可增加 loading 状态，请求期间禁止重复提交或显示骨架屏。

### 4.2 分页与「加载更多」

- **分页条**：根据接口返回的 `total` 与 `page_size` 计算总页数，切换页码时带新 `page` 重新请求列表。
- **加载更多**：保持 `page_size` 不变，每次在原有列表后追加请求 `page+1` 的结果；需注意去重（同一篇 id 不重复展示）。

### 4.3 首页最新几条

- 首页仅需最新 3 条时，使用 `/api/news/homepage?limit=3` 即可，无需分页参数；实现要点见第一节。

## 五、测试与验证

- **首页资讯**：访问首页，确认「市场资讯」区域展示最新几条，时间与摘要格式正确，「更多」跳转资讯频道。
- **资讯列表**：在资讯频道切换分类、修改关键词、翻页，确认与接口返回一致且无重复/缺漏。
- **API 健壮性**：在无 `read_count` 或无 `news_categories` 表的环境下，确认接口不 500 且返回合理默认数据。
