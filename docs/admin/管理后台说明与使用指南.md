# 管理后台说明与使用指南

本文档整合管理后台的架构说明、重构总结、刷新问题修复、用户密码功能及历史行情数据功能的说明与使用方式。

---

## 一、管理后台现代化重构方案

### 1.1 重构目标

将传统 JavaScript 管理后台重构为 **Vue 3 + TypeScript + Vite** 架构，解决 DOM 时序、模块化、状态管理等问题。

### 1.2 技术栈

- **前端**：Vue 3.4+（Composition API）、TypeScript 5.0+、Vite 5.0+、Vue Router 4、Pinia
- **UI**：Element Plus、Tailwind CSS
- **工具**：ESLint + Prettier、Vitest

### 1.3 目录结构要点

```
admin/ (或 admin-modern/)
├── src/
│   ├── components/   # common, dashboard, logs, users, quotes 等
│   ├── views/        # LoginView, DashboardView, LogsView, UsersView, QuotesView 等
│   ├── stores/       # auth, logs, users, quotes, app (Pinia)
│   ├── services/     # api, auth.service, logs.service, users.service, quotes.service
│   ├── types/        # 类型定义
│   ├── utils/        # request, storage, date, format
│   ├── router/
│   ├── App.vue
│   └── main.ts
├── vite.config.ts    # base 生产环境为 /admin/
└── package.json
```

### 1.4 核心架构要点

- **状态管理**：Pinia store（如 logs、users、quotes），统一请求与分页。
- **服务层**：Axios 封装，请求/响应拦截器，401 时调用 authStore.logout()。
- **路由**：createWebHistory，生产环境 base 为 `/admin/`；路由守卫校验 requiresAuth。
- **迁移策略**：环境搭建 → 核心功能迁移（认证、日志、用户、仪表板）→ 高级功能 → 测试与优化。

### 1.5 重构优势

- 类型安全、响应式与模块化更好；Vite 热更新与构建快；路由懒加载与 Tree Shaking；与现有后端 API 保持兼容。

## 二、重构总结与独立运行

### 2.1 目标与结构

- **完全独立运行**：管理后台不依赖 frontend 目录。
- **独立登录与 Dashboard**：独立 JWT 认证，登录后进入 Dashboard。

**核心文件（传统/独立模式示例）**：

```
admin/
├── index.html
├── config.js
├── css/admin.css
├── js/admin.js
└── start_admin_standalone.py   # 独立启动脚本
```

### 2.2 配置示例

```javascript
const ADMIN_CONFIG = {
    API: {
        BASE_URL: 'http://localhost:5000/api/admin',
        TIMEOUT: 30000,
        RETRY_TIMES: 3
    },
    AUTH: {
        TOKEN_KEY: 'admin_token',
        LOGIN_URL: '/admin/',
        LOGOUT_URL: '/api/admin/auth/logout'
    }
};
```

### 2.3 启动与访问

```bash
# 独立管理后台
python start_admin_standalone.py
```

- **管理后台**：http://localhost:8001
- **后端 API**：http://localhost:5000
- **默认账号**：admin / 123456（以实际配置为准）

### 2.4 功能模块概览

- 统计卡片、图表、最近活动、用户管理、行情数据、数据源配置、数据采集、系统监控等。

### 2.5 故障排除

- **端口占用**：`netstat -ano | findstr :8001`，必要时 `taskkill /PID <pid> /F`。
- **API 连接失败**：确认后端 5000 端口与防火墙。

## 三、管理端刷新 404 修复（生产环境）

### 3.1 问题与原因

- **现象**：生产环境管理端登录页或子路径刷新后出现 404。
- **原因**：Nginx 未正确处理 Vue Router history 模式；缺少 SPA fallback。

### 3.2 解决方案要点

**Nginx 管理端 fallback**：

```nginx
location /admin/ {
    proxy_pass http://admin_server/;
    proxy_intercept_errors on;
    error_page 404 = @admin_fallback;
}

location @admin_fallback {
    proxy_pass http://admin_server/index.html;
    # 代理头等
}
```

**静态资源**：`location ~ ^/admin/assets/` 正确代理并可选缓存。

### 3.3 前端配置确认

**Vue Router**（`admin/src/router/index.ts`）：

```typescript
history: createWebHistory(process.env.NODE_ENV === 'production' ? '/admin/' : '/')
```

**Vite**（`admin/vite.config.ts`）：

```typescript
base: process.env.NODE_ENV === 'production' ? '/admin/' : '/'
```

### 3.4 部署步骤

1. 备份现有 Nginx 配置，应用 `docs/fixed/nginx_admin_fix.conf`（或等效配置）。
2. `nginx -t` 测试后 `nginx -s reload`。
3. 验证：访问 `https://your-domain.com/admin/login` 并刷新，应正常显示。

### 3.5 故障排除

- 仍 404：查 Nginx 错误日志、确认管理端服务（如 8001）正常。
- 静态资源失败：检查 `/admin/assets/` 代理与 Vite 构建产物路径。
- 路由异常：确认 Router 与 Vite 的 base 均为 `/admin/`。

## 四、用户密码功能

### 4.1 功能说明

- **修改用户密码**：管理员为用户直接设置新密码。
- **初始化用户密码**：重置为默认密码（如 `bingfengtang$91`）。

### 4.2 后端接口

- **PUT** `/api/admin/users/{user_id}/password`  
  - 请求体：`{ "new_password": "<新密码>" }`  
  - 返回：`{ "message": "密码修改成功" }`

- **POST** `/api/admin/users/{user_id}/password/reset`  
  - 默认密码：`bingfengtang$91`  
  - 返回：`{ "message": "密码已重置为默认值", "default": "bingfengtang$91" }`

### 4.3 前端与影响范围

- 用户管理页操作列增加「修改密码」「初始化密码」。
- 修改密码：弹窗输入新密码并提交；初始化密码：确认后调用重置接口。
- 涉及：`backend_api/admin/users.py`，`admin/src/services/users.service.ts`，`admin/src/stores/users.ts`，`admin/src/views/UsersView.vue`。

### 4.4 使用说明

1. 登录管理端，进入「用户管理」。
2. 在用户行「更多」下拉中选择「修改密码」或「初始化密码」。
3. 初始化密码默认值以接口返回为准（如 `bingfengtang$91`）。

## 五、历史行情数据功能

### 5.1 功能概述

在管理端「行情数据」中增加历史行情数据标签页：展示、筛选与行内编辑。

### 5.2 功能特性

- **展示与筛选**：按股票代码、开始/结束日期筛选；可选包含交易备注；分页。
- **行内编辑**：编辑开盘价、收盘价、最高价、最低价、成交量、成交额、换手率、备注等；基本价格合理性校验；保存/取消。
- **格式化**：价格两位小数；涨跌颜色；成交量/成交额单位（万、亿）；换手率百分比。

### 5.3 接口

- **GET** `/api/quotes/history?code={stock_code}&page=&size=&start_date=&end_date=&include_notes=` — 获取历史行情。
- **PUT** `/api/quotes/history/{code}/{date}` — 更新单条历史行情。
- **GET** `/api/quotes/stocks/list` — 获取股票列表。

### 5.4 使用步骤

**查看历史行情**  
1. 进入「行情数据」→「历史行情数据」标签。  
2. 选择股票、可选日期范围与「包含交易备注」。  
3. 点击「刷新」获取数据。

**修改数据**  
1. 在表格行点击「编辑」。  
2. 修改字段后「保存」或「取消」。  
3. 遵守校验规则（如最高价 ≥ 开盘价/收盘价等）。

### 5.5 涉及文件

- 前端：`admin/src/services/quotes.service.ts`（HistoricalQuoteParams、getHistoricalQuotes、updateHistoricalQuote、getStockList），`admin/src/views/QuotesView.vue`（历史行情标签、筛选、表格、行内编辑）。
- 后端：FastAPI + SQLAlchemy，历史行情表。

### 5.6 注意事项与扩展

- **注意**：权限控制、修改前备份、并发编辑与审计日志。
- **扩展方向**：批量编辑、Excel 导入、导出 Excel/CSV、统计与指标、与外部数据源同步。

## 六、股票基本信息与相对强度（补充）

### 6.1 菜单

侧栏菜单名为 **股票基本信息**（路径 `/stock-basic`），页面含 A 股 / 港股切换，以及「基本信息查询」「股本导入」「股本导出」「**股价相对强度**」等 Tab。

### 6.2 股价相对强度 Tab

- **仅 A 股**：展示 `rs_ratings` 预计算结果，默认按 **RS 评级从高到低**。
- 可按代码/名称、基准日、最低评级筛选；分页浏览。
- 计算口径为 **前复权** 多周期截面排名；数据依赖采集流程节点 `rs_rating_cn` 日终写入。
- **历史追溯**：工具栏「历史追溯」或行内「追溯」打开对话框，按股票/日期区间查看历史 RS；也可跳转前台 `stock_rs_trace.html`。
- 接口：
  - 截面列表 `GET /api/admin/stock-basic/rs-ratings`
  - 历史 `GET /api/admin/stock-basic/rs-ratings/history`
- 算法与运维说明：[`docs/indicators/股价相对强度_RS_Rating.md`](../indicators/股价相对强度_RS_Rating.md)
- 流程挂载：[`docs/fixed/COLLECTION_WORKFLOW.md`](../fixed/COLLECTION_WORKFLOW.md)
