# 行业板块实现与领涨股问题说明

本文档整合行业板块数据采集的实现要点与领涨股数据缺失问题的分析与解决方案。

---

## 一、实现与采集概述

### 1.1 数据来源与表结构

- **接口**：AKShare `ak.stock_board_industry_name_em()`，获取行业板块实时行情。  
  **列名兼容**（2025 起）：`领涨股票` / `领涨股票-涨跌幅`（旧版为 `领涨股` / `领涨股涨跌幅`）；归一化见 `industry_board_normalize.py`。
- **存储表**：`industry_board_realtime_quotes`。

**表结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| board_code | VARCHAR(20) | 主键，板块代码 |
| board_name | VARCHAR(100) | 板块名称 |
| latest_price | FLOAT | 最新价 |
| change_amount | FLOAT | 涨跌额 |
| change_percent | FLOAT | 涨跌幅 |
| total_market_value | FLOAT | 总市值 |
| volume | FLOAT | 成交量 |
| amount | FLOAT | 成交额 |
| turnover_rate | FLOAT | 换手率 |
| leading_stock_name | VARCHAR(100) | 领涨股名称 |
| leading_stock_code | VARCHAR(20) | 领涨股代码 |
| leading_stock_change_percent | FLOAT | 领涨股涨跌幅 |
| update_time | VARCHAR | 更新时间 |

### 1.2 采集与改进版采集器

- **采集器**：`backend_core/data_collectors/akshare/realtime_stock_industry_board_ak.py`  
  - 字段映射：如 `"领涨股"` → `leading_stock_name`，数据保存与错误处理已具备。
- **改进版（调试用）**：`realtime_stock_industry_board_ak_improved.py`  
  - 用于排查领涨股为空的问题：详细日志、接口返回列名与领涨股字段存在性检查、非空值统计、错误信息细化。

数据流：**AKShare 接口 → 采集器 → 数据库 → API → 前端**。

### 1.3 板块成分股（board_code ↔ stock_code）

- **表**：`industry_board_constituents`（主键 `board_code` + `stock_code`）
- **采集器**：`backend_core/data_collectors/akshare/industry_board_constituents_ak.py`  
  - 接口：`ak.stock_board_industry_cons_em(symbol=board_code)`  
  - 从 `industry_board_basic_info` 读取板块列表，按板块 UPSERT 成分股（不删除存量）
- **调度**：`main.py` 工作日 16:30（`SCHED_INDUSTRY_CONS_*`），休市日跳过
- **手动同步**：`python backend_core/data_collectors/akshare/industry_board_constituents_ak.py`
- **迁移**：`python migrations/add_industry_board_constituents.py`

**API**（`backend_api/market_routes.py`）：

| 路径 | 说明 |
|------|------|
| `GET /api/market/industry_board/{board_code}/stocks` | 成分股分页列表（含实时涨跌幅） |
| `GET /api/market/industry_board/{board_code}/top_stocks?limit=10` | 涨幅 Top N |
| `GET /api/market/stock/{code}/industry_boards` | 个股所属板块 |

**管理端**：`POST /api/admin/quotes/realtime/industries/constituents/sync` 触发同步；`POST .../constituents/delete` 删除成分。

查询工具：`backend_api/utils/industry_board_query.py`（选股/PVFRS 行业过滤复用）。

## 二、领涨股数据缺失问题分析与解决方案

### 2.1 问题描述

**现象**：行业板块采集时，`leading_stock_name`、`leading_stock_code`、`leading_stock_change_percent` 常为 `null`，前端无法展示领涨股信息。

**影响**：行情中心行业板块的领涨股无法显示，影响体验。

### 2.2 问题分析

#### 数据采集与表结构

- 采集器字段映射正确，保存逻辑与错误处理存在。
- 表结构及主键、类型设置合理。

#### 可能原因

1. **AKShare 返回中领涨股字段为空**（接口侧未给值或仅部分时段有值）。
2. **字段名不一致**：代码期望的列名与 AKShare 实际返回不一致。
3. **采集时机**：非交易时间或数据未更新时段。
4. **网络或调用失败**：请求失败或超时导致无数据。

### 2.3 解决方案

#### 方案 1：用改进版采集器做调试

- 运行 `realtime_stock_industry_board_ak_improved.py`，查看：
  - 接口返回的列名；
  - “领涨股”“领涨股涨跌幅”“领涨股代码”是否存在及非空数量；
  - 保存结果与错误信息。
- 根据输出判断：是字段缺失、字段名不一致，还是接口本身经常返回空。

#### 方案 2：核对 AKShare 实际返回

- 对照调试输出中的列名，确认与当前字段映射一致。
- 若列名不同，在采集器中调整映射；若接口文档有更新，参考最新文档。

#### 方案 3：采集时机与策略

- 尽量在交易时间内采集。
- 可适当提高采集频率，并做简单数据有效性检查（如非空比例）。

### 2.4 实施步骤

**步骤 1：运行改进版采集器**

```bash
cd backend_core
python data_collectors/akshare/realtime_stock_industry_board_ak_improved.py
```

**步骤 2：看调试输出**

关注：列名列表、领涨股相关列是否存在、非空条数（例如 `非空值 45/86`）。

**步骤 3：按结果处理**

- **字段存在但多为空**：考虑采集时间、接口在不同时段的表现，或是否需更换/补充数据源。
- **字段不存在或列名不同**：修改采集器字段映射，或查阅 AKShare 文档/源码。
- **采集报错**：检查网络、AKShare 版本与错误日志。

### 2.5 诊断检查清单

- **基础**：采集器能否正常跑、数据库连接、表结构是否正确。
- **数据**：接口是否返回数据、字段映射是否正确、领涨股列是否存在且有值。
- **流程**：采集→落库、查询→API 返回、API→前端展示是否一致。

### 2.6 预期结果与后续优化

- **成功**：领涨股三字段有值、正确落库、API 返回完整、前端正常展示。
- **失败**：记录详细错误、保留降级展示（如不展示领涨股）、监控空值率。

**后续建议**：  
- 对领涨股字段做空值率监控与告警；  
- 按交易时间与数据更新节奏优化采集频率与重试；  
- 前端展示数据更新时间、加载状态与刷新能力。

---

## 三、总结

- **问题核心**：行业板块采集中领涨股相关信息经常为空，导致前端无法显示。
- **解决思路**：用改进版采集器定位是接口列名/字段缺失还是时机问题；核对并修正字段映射；优化采集时机与数据质量监控。
- **预期效果**：在接口有数据的前提下，稳定获取并展示行业板块领涨股名称、代码与涨跌幅。

**下一步**：运行 `realtime_stock_industry_board_ak_improved.py`，根据调试结果做字段映射或采集策略的针对性修改。
