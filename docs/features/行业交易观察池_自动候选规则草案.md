# 行业交易观察池 — 自动候选规则草案（v0）

**状态：** v0 已落地（2026-11-12）— 日批 / API / 市场分析「行业观察池候选」/ 管理端观察锁；默认 **不**静默改正式池。  
**目标：** 日终自动给出「建议纳入 / 建议移出」名单；**正式观察池**仍以 `industry_board_basic_info.trade_observe_flag` 为准，须人工确认（或一键采纳）后才改写。  
**关联：** [`板块中长线与短线入场闸门_v1约定.md`](./板块中长线与短线入场闸门_v1约定.md)、[`板块中长线与短线入场闸门_v2规划.md`](./板块中长线与短线入场闸门_v2规划.md)

**实现入口：** `backend_core/board_observe/` · `GET/POST /api/board_observe/*` · 工作流节点 `board_observe_candidates_daily` · `migrations/add_board_observe_candidate*.py`

**跨来源说明：** 候选与闸门按同花顺行业代码计算；若东财等同名行业已勾「交易观察」，按**板块名称** OR 视为正式池。采纳时会把同名其它来源的 `trade_observe_flag` 一并同步。

---

## 1. 为什么要拆「候选」与「正式池」

| 概念 | 含义 | 谁决定 |
|------|------|--------|
| **正式观察池** | `trade_observe_flag=true` 的行业；中长线闸门 / 池内 RS·估值分位只在此子集跑 | 人工（管理端开关）；可一键采纳候选 |
| **自动候选** | 当日算法给出的 suggest_in / suggest_out | 日批计算，**不**直接改 flag |

禁止用「中长线闸门结果」反推入池：闸门依赖观察池，会造成循环依赖。候选规则只吃**全行业可用**的价量/RS/主线证据。

---

## 2. 宇宙与硬排除

- **宇宙：** 同花顺行业板（`board_kind=industry`），且前端可见（`frontend_visible_flag≠false`）。
- **硬排除（不得 suggest_in）：**
  - 无有效 60 窗 `sector_slope` / `board_env`（样本或 R² 不足导致不可用）
  - 板指数历史不足 **120** 根（建议入池门槛低于板 RS 的 253，避免新板永远进不来；RS 缺失时候选降权，见下）
  - 人工 **锁死排除**（`observe_lock=exclude`，见 §6）

概念板：本草案**不做**中长线观察池候选（与闸门约定一致）。

---

## 3. 建议纳入（suggest_in）

满足 **入场分 ≥ 入场阈值**，且非硬排除、非锁死排除。  
默认 **入场阈值 = 2**（满分约 4～5，见下）。连续 **2** 个交易日达标才写入「可一键采纳」队列（防一日噪声）；首日仅标 `candidate_pending`。

### 3.1 计分（每条至多 1 分，可叠加）

| 分 | 条件 | 数据 |
|----|------|------|
| +1 **价·中** | `board_env(60)` 为走强（假强 `strong_low_r2` **不计**） | `sector_slope` / board_env |
| +1 **价·长** | `board_env(120)` 走强，或斜率 ≥ 0 且非走弱 | 同上 |
| +1 **量** | 近 20 日 `main_net_inflow` 合计 ≥ 0；若 `slope_source=equal_weight_return` 则须 **> 0** | `board_fund_flow_daily` |
| +1 **相对强度** | 全行业 `board_rs_rating ≥ 60`（低于闸门可配的 70，故意更宽，只表示「值得盯」） | `board_rs_ratings` |
| +1 **主线/焦点**（可选加分，默认启用） | 近 10 日复盘主线命中 ≥ 2，或当日行业涨幅/资金进入 Top15 | 复盘 / 资金流排名 |

**一票否决（当日不得 suggest_in，即使分够）：**

- `board_trend_*` ∈ 明确长弱（与闸门 `TREND_AVOID_MIDLONG` 对齐，如全面走弱等）
- `fund_stage ∈ {decline, distribute}` **且** 60 窗走弱
- 全行业板 RS **&lt; 30** 且 60 走弱（与闸门回避精神一致，但用全市场 RS，不依赖池内分位）

**RS / 资金阶段缺失：** 不计该分，**不**因缺失一票否决；但若价量两分都未拿到，最高也到不了阈值。

### 3.2 容量

- 建议纳入队列按 **分数 ↓、板 RS ↓、60 斜率 ↓** 排序。
- 日批最多产出 **SuggestIn Top N**（默认 **N=15** 新候选；已在正式池的不占「新候选」名额，只刷新其 `score` 供对照）。
- 正式池目标软上限 **M=40**（当前约 43，可调）：若正式池已 ≥ M，则 suggest_in 仅展示、默认**不**进入一键批量采纳（需逐个确认）。

---

## 4. 建议移出（suggest_out）

仅针对 **已在正式池** 的行业。连续 **3** 个交易日满足「移出条件」才进入可采纳移出队列（与中长线粘性天数对齐）。

**移出条件（满足任一）：**

1. 60 与 120 **均为走弱**；或  
2. 入场分连续 3 日 **&lt; 1**（价量相对强度几乎全灭）；或  
3. `fund_stage=decline` 且 60 走弱；或  
4. 全行业板 RS **&lt; 30** 且近 20 日资金合计 &lt; 0  

**不因** 中长线闸门=`回避`/`观望` 自动移出（闸门是池内评估，移出是宇宙收缩）。

**锁死纳入**（`observe_lock=include`）的板：可算分展示，但 **禁止** suggest_out 自动进入采纳队列。

---

## 5. 与闸门、展示的关系

```
全行业证据 → 候选日表（suggest_in/out + score）
                ↓ 人工确认 / 一键采纳
         trade_observe_flag（正式池）
                ↓ 既有日批
         中长线闸门 / 池内 RS·估值分位
```

| 界面 | 行为 |
|------|------|
| 管理端「板块成分股」 | 保留现有「交易观察」开关；增加「锁死纳入 / 锁死排除 / 跟随候选」；展示最近候选分与原因 |
| 市场分析「板块入场闸门」 | 「仅观察池」仍滤正式池；可选旁路「今日候选」角标 |
| 新页或闸门旁栏 | 候选入/出列表 + 一键采纳（写 flag） |

Shadow 默认：**只算候选、不改 flag**（与闸门 hard_filter 哲学一致）。

## 6. 锁死与审计

建议扩展正式池元数据（名称可调）：

| 字段 | 含义 |
|------|------|
| `trade_observe_flag` | 正式是否在池（不变） |
| `observe_lock` | `follow`（默认）/ `include` / `exclude` |
| `observe_source` | `manual` / `adopted_auto` / `sync` |
| `observe_updated_at` / `observe_updated_by` | 审计 |

采纳候选时：仅更新 `follow` 板；`include`/`exclude` 跳过并记日志。

## 7. 落库与工作流（实现时）

| 项 | 建议 |
|----|------|
| 表 | `board_observe_candidate_daily`（`trade_date, board_code, action, score, evidence_json, sticky_count, adoptable`） |
| 节点 | 挂在斜率 / 资金 / 板 RS 之后、**`board_gates_daily` 之前或并行**（候选不依赖闸门；闸门仍读正式 flag） |
| API | `GET /api/board_observe/candidates`；`POST .../adopt`（批量改 flag） |
| 配置 | `OBSERVE_CANDIDATE_IN_THRESHOLD=2`、`IN_CONFIRM_DAYS=2`、`OUT_CONFIRM_DAYS=3`、`TOP_N=15`、`SOFT_CAP=40` |

回测验收（上线前）：

1. 候选池日均规模是否稳定（避免一天 5 个、一天 80 个）  
2. 采纳后 20 日内中长线「可配」命中率是否高于随机行业对照  
3. suggest_out 后 20 日再被 suggest_in 的抖动率

## 8. 明确不做（v0）

- 日终静默改写 `trade_observe_flag`  
- 用中长线 `可配/回避` 决定入/出池  
- 概念板自动进中长线观察池  
- 估值单独决定入池（极贵仅作展示降权，v0 不写进一票否决）
