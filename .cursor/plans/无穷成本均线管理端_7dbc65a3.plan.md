# 管理端「无穷成本均线指标」方案（人工 + 自动）

## 目标与口径

- **界面**：在 [admin/src/views/IndicatorsView.vue](admin/src/views/IndicatorsView.vue) 的 **「指标数据查询」** 内增加子标签 **「无穷成本均线指标」**（与 MA/MACD/KDJ 等并列）。
- **含义（工程可算）**：采用此前约定的 **自数据起点起的累计成交量加权均价**（累计 `amount` / 累计 `volume`，与逐日 `amount/volume` 再对 volume 加权等价），**不等价**于通达信筹码 `COST`；界面文案需简要说明，避免与商业软件逐点对比争议。
- **人工计算**：用户在 **「指标数据生成」** 中输入代码、市场、勾选 **无穷成本均线**（新 indicator key），点击 **「生成指标数据」** —— 与现有 MACD 等流程一致（调用 `POST /api/admin/indicators/generate`）。
- **自动计算**：
  - 同一页面 **批量**：「为全部自选股生成指标」「为全部A股生成指标」在勾选该指标时一并计算（[indicators.py](backend_api/admin/indicators.py) 中 `generate-batch-watchlist` / `generate-batch-all-a-shares` 需扩展）。
  - **数据采集侧（可选但建议一致）**：在 [admin/src/views/DataCollectView.vue](admin/src/views/DataCollectView.vue) 各指标勾选列表中增加同一 key，并在 [data_collection_api.py](backend_api/stock/data_collection_api.py) 的 `_generate_indicators` 分支中接入，保证「采完 K 线顺带算指标」行为与其它指标一致。

## 后端设计

### 1. 新表与模型

- 在 [backend_api/models.py](backend_api/models.py) 增加表（名称示例）：`infinite_cost_indicators` 或 `icost_indicators`。
- 字段建议：`code`（PK 部分）、`date`（PK 部分）、`market_type`（CN/HK）、`ic_price`（Float，当日累计成交均价线）、`cum_amount`、`cum_volume`（可选，便于审计与增量重算）。
- 复合主键与 [MACDIndicators](backend_api/models.py) 等保持一致；港股 `date` 类型与现有 HK 表一致（String）。

### 2. 纯计算模块

- 新建 [backend_core/utils/infinite_cost_calculator.py](backend_core/utils/infinite_cost_calculator.py)（或同类命名）：
  - 输入：按日期升序的 OHLCV + `amount`（从 `HistoricalQuotes` / `HistoricalQuotesHK` 取数时带上 `amount`、`volume`）。
  - 递推：`cum_amt += amount_t`，`cum_vol += volume_t`（`volume<=0` 跳过或沿用前日，**在函数内固定一种规则并写注释**）；`ic_t = cum_amt / cum_vol`（`cum_vol==0` 时 NULL 或跳过）。
  - 若 `amount` 缺失：回退 **典型价 × volume**（与前期方案 B 一致），并在日志/文档标注。

### 3. Admin API

- 在 [backend_api/admin/indicators.py](backend_api/admin/indicators.py)：
  - 新增 `GET /infinite_cost`（或 `/icost`）：分页与筛选参数对齐 `GET /macd`（`code`、`market_type`、`start_date`、`end_date`、`page`、`page_size`）。
  - 在 `POST /generate` 中增加 `elif indicator == "icost"`（或约定英文名 `infinite_cost`）分支：读全历史 K 线 → 计算 → `merge` 写入新表。
  - 在 `generate_batch_watchlist` 与 `generate_batch_all_a_shares` 的指标分发处增加同一分支（与现有 `ma`/`macd` 循环结构一致）。

### 4. 数据采集链路

- [data_collection_api.py](backend_api/stock/data_collection_api.py)：`indicators` 列表支持新 key；`_generate_indicators` 内调用与单股 generate 相同的计算/落库逻辑（可抽私有函数避免重复）。

## 前端设计

### 1. [IndicatorsView.vue](admin/src/views/IndicatorsView.vue)

- **查询区**：新增 `<el-tab-pane label="无穷成本均线" name="icost">`（名称与路由参数一致），筛选区复用现有 `code/market_type/start_date/end_date`，表格列：`code`、`date`、`ic_price`（及可选 `cum_amount`/`cum_volume`），价格列保留 2～4 位小数。
- **脚本**：`fetchData` 已请求 `/indicators/${activeIndicator.value}` —— 后端 path 与 `name` 一致即可。
- **指标数据生成**：`allIndicatorTypes` 增加 `'icost'`；勾选区增加一项；`getIndicatorLabel` 增加中文名。

### 2. [DataCollectView.vue](admin/src/views/DataCollectView.vue)（若纳入自动）

- 所有 `allIndicators` / checkbox 列表增加 `icost`（与 `ma`、`kdj` 等并列），避免采集任务只算旧指标。

## 说明

- **indicator key**：建议统一为短名 `icost`（或 `inf_cost`），前后端、采集配置同一字符串。
- **PostgreSQL**：写入 `code` 时保持与 [HistoricalQuotes](backend_api/models.py) 一致类型（字符串），避免 text/int 混比问题。
