# Cursor 办公室与家里 PC 如何同步「Agent / 提示词相关」内容

## 先分清两类数据

| 类型 | 典型内容 | 是否靠账号自动云同步 |
|------|-----------|----------------------|
| **编辑器与账号设置** | `settings.json`、快捷键、扩展、部分 UI 状态 | **可以** — 同一 Cursor 账号 + 开启 Settings Sync |
| **对话 / Agent 工作历史** | Composer、Chat、Agent 线程里的消息与上下文 | **通常不能** — 历史主要存在本机 SQLite，社区长期反馈「聊天云同步」仍是需求而非默认能力 |

你问的「agent 提示词工作历史」若指 **和 Agent 来回对话的那段聊天记录**，下面按「对话历史」处理；若指 **项目里的规则与提示词文件**，见文末「项目级」一节。

---

## 方案一：内置 Settings Sync（两台都登录同一账号）

1. 两台电脑都用 **同一个 Cursor 账号** 登录。
2. 打开 **Settings Sync**（与 VS Code 类似：账户头像 → 开启同步）。
3. 在 **Configure** 里勾选需要同步的项（设置、快捷键、扩展、片段等）。

**能同步的**：开发环境一致性、扩展、用户级 AI 相关配置（若文档/界面里包含在同步项中）。

**不能指望自动同步的**：各工作区下的 **完整聊天 / Agent 会话列表**（数据在本地库中，见下）。

---

## 方案二：手动拷贝聊天数据库（同一项目路径时可用）

Cursor 把会话相关数据放在本机，常见结构（Windows）：

- 工作区维度：[`%APPDATA%\Cursor\User\workspaceStorage`](%APPDATA%\Cursor\User\workspaceStorage) 下各子目录里的 `state.vscdb`（SQLite）。
- 全局存储也可能很大，社区工具会同时提到 [`globalStorage\state.vscdb`](globalStorage)。

**做法概要**：在 **完全退出 Cursor** 后，将源机器上对应工作区文件夹（或文档推荐的 `state.vscdb`）复制到目标机器 **相同相对结构**；路径或工作区 ID 不一致时容易对不上，需谨慎。

**风险**：版本不一致、路径变化、合并冲突可能导致异常；操作前备份。

---

## 方案三：导出/导入类工具（更适合「带走对话」）

社区常见做法（非 Cursor 官方内置功能）：

- **扩展 / 工具**：例如 GitHub 上的 [cursor-chat-transfer](https://github.com/ibrahim317/cursor-chat-transfer)（导出为 `.cursor-chat.json` 再在另一台导入；导入后需 **完全退出并重启 Cursor**）。
- **CLI 同步**：例如社区介绍的 `cursaves` 类工具，用私有 git 仓库存快照，在另一台 `pull` 后同样需重启 Cursor（且多数工具要求操作时 Cursor 关闭或遵循其说明）。

**注意**：对话里可能含代码与隐私，若用网盘/git，请使用 **私有** 仓库并注意保密。

---

## 项目级「提示词 / 规则」——用 Git 即可

若你指的是 **仓库里的 Agent 规则、技能、文档**（例如 [`.cursor/rules/`](.cursor/rules/)、`AGENTS.md`、团队共享的提示词模板），这些是普通文件：

- **办公室提交 → 远程仓库 → 家里拉取**，即可同步；与 Cursor 账号云同步无关。

---

## 建议你怎么选

- **只想环境一致**：同一账号 + **Settings Sync**。
- **要把办公室里的 Agent 对话原样搬到家里**：依赖 **手动数据库拷贝** 或 **导出/导入 / CLI** 之一，并接受路径与版本限制。
- **只想规则与项目约定一致**：把规则放进仓库并用 **Git**。

---

## 可选确认（避免理解偏差）

若你所说的「提示词工作历史」特指 **Cursor 界面里「Rules / Project Rules」的编辑历史** 而非聊天内容，一般以 **当前磁盘上的规则文件** 为准，跨机仍以 **Git + Settings Sync** 组合最稳。
