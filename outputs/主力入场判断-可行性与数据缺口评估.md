# 主力入场判断 —— 可行性与数据缺口评估

> 评估对象：`个股分析页`（`analysis.html` 的「个股分析」tab，及 `stock.html`「交易分析」tab 内嵌的同一模块）
> 评估方式：通读前端模块 / 后端 API / 采集器 / 建表迁移，并**对生产库做实测取数**
> 评估日期：2026-10-07

---

## 一、结论

| 判断目标 | 现有能力 | 关键约束 |
|---|---|---|
| **哪个时间段**主力在入场 | **可以，但窗口极短** | 个股资金流仅 **15 个交易日**（2026-09-08 ~ 09-29）；再往前只能用日线量价做间接推断 |
| **哪个价位区间**主力在入场 | **可以给出近似值，但不能给出分布** | 可算「主力净流入加权均价」；无筹码分布 / 成本分布数据，无法给出「多少筹码在哪个价位」 |
| **是谁**在买（席位主体） | **不可判断** | 龙虎榜仅 1 个交易日；无机构持仓 / 北向 / 逐笔成交落库 |

**一句话**：**能**回答「最近约 3 周里，主力资金在哪个价位带净买入、哪几天在买」；**不能**回答「主力在什么价位建了多少仓、成本是多少」，也**不能**回溯更早的时间段。

## 三、现在就能算出来的东西

### 3.1 数据基础

- 个股资金流日表 `stock_fund_flow_daily`（`backend_api/models.py:521`）字段：
  `net_amount`（主力净额）、`inflow_amount`、`outflow_amount`、`turnover_amount`（成交额）、`turnover_rate`、`current_price`。
  **注意：只有汇总的流入/流出/净额，没有超大单 / 大单 / 中单 / 小单分档。**（分档只在**板块级** `board_fund_flow_daily` 有，但实测 3 335 行中仅 65 行有 `super_large_net_inflow`，等于没落。）
- 行情日表 `historical_quotes` 提供 `amount`、`volume`，可反推当日均价。
  **实测校准**：`amount / volume / 100 ≈ close`（`volume` 单位是「手」），15 个交易日比值稳定在 0.97 ~ 1.02，可直接当 VWAP 用。

### 3.2 核心公式：主力净流入加权均价

```
VWAP_i      = amount_i / volume_i / 100          # 当日均价
主力成本重心 = Σ(net_amount_i × VWAP_i) / Σ(net_amount_i)   , 仅取 net_amount_i > 0 的日子
```

### 3.3 实测算例（2026-09-08 ~ 09-29，15 个交易日）

| 代码 | 名称 | 区间净额 | 主力净流入加权均价 | 窗口内价格区间 | 相对最新收盘 |
|---|---|---|---|---|---|
| 300750 | 宁德时代 | +42.11 亿 | **316.93** | 285.74 ~ 346.60 | 浮盈 10.49% |
| 688008 | 澜起科技 | +29.56 亿 | **207.89** | 183.21 ~ 233.19 | 浮亏 2.21% |
| 600900 | 长江电力 | +19.40 亿 | **28.29** | 27.63 ~ 28.84 | 浮亏 0.31% |

判读示例：宁德时代主力在 **317 元附近**净买入约 42 亿，随后价格一路下行至 287 元 —— 主力**已被套约 10%**，属于「高位承接」型入场；长江电力的加权均价 28.29 与最新价几乎持平，属于「成本区盘整」型。

### 3.4 配套可得的辅助判断

| 指标 | 来源 | 说明 |
|---|---|---|
| 净流入持续时间 | `stock_fund_flow_daily` | 连续 N 日净流入 = 入场更可能是「一段建仓」而非单日脉冲 |
| 净额 / 成交额占比 | 同上 | 主力参与度；占比高说明当日由大资金主导 |
| 量价配合 | `historical_quotes` | 放量上涨 + 净流入 = 主动建仓；缩量下跌 + 净流入 = 被动接盘 |
| 价位聚集区 | `backend_core/analysis/volume_profile.py` | POC / VAH / VAL + 24 个价格桶，已在个股分析页「价格行为 → 阻力支撑位」展示 |
| 板块共振 | `board_fund_flow_daily` | GMS 策略已用板块主力净额做降权（`gms/board_resonance.py:676`） |
| 集合竞价 | `stock_auction_daily` | 仅 8 个交易日、771 只股票，样本太小 |

## 四、口径与方法论上的固有局限

**这几条不是缺数据，而是这类判断本身的天花板，必须写进结论里：**

1. **「主力」是推断，不是事实。** 同花顺/东财的「资金流」是按**单笔成交金额分档**推断的（大单 ≈ 主力），A 股无法确知账户归属。同一笔机构拆单买入会被记成「中单」，散户的单笔大额买入会被记成「主力」。
2. **净额是「净」不是「买」。** `net = 流入 - 流出`，+42 亿可能是「买 200 亿同时卖 158 亿」，换手极高时的巨额净额与真实建仓含义完全不同。
3. **加权均价 ≠ 持仓成本。** 它只是「净流入日的价格重心」。若主力在净流出日也在卖，卖出部分的价格没有从重心里扣掉。
4. **无复权处理。** 窗口内如有分红除权，前后价格不可比。项目有 `stock_adj_factor` 与 `apply_qfq_to_bars`（`backend_api/utils/adj_quotes.py:1092`），但当前资金流链路未接。
5. **窗口过短 → 统计不显著。** 15 个交易日的样本，无法区分「主力建仓」与「短期博弈资金进出」。

## 五、补齐路线（按成本从低到高）

### 路线 A：给现有日线补上「筹码分布」模型（**推荐首选，零新增外部数据**）

用 `historical_quotes`（29 年量价 + 换手率）实现流通业内标准的 **CYQ 筹码分布**：

- 每日按 `[low, high]` 做三角形分布摊量（比现有 `volume_profile.py` 的**均匀摊量**更接近真实）
- 按 `turnover_rate` 对历史筹码做**换手衰减**（现有 VP 完全不衰减，所以老成交量权重虚高）
- 输出：获利盘比例、90% 成本区间、成本集中度、单峰密集识别、**主力成本区近似**

**唯一障碍**：`historical_quotes.turnover_rate` 填充率仅 **17.2%**（近一年 143.6 万行中 74.4 万行有值）。项目已有回填采集器 `backend_core/data_collectors/akshare/historical_turnover_rate.py`，但默认只回溯 30 天且定时任务默认关闭（`main.py:332` `SCHED_AKSHARE_TURNOVER_ENABLED=false`）。

> 具体改造：开启该任务并把回溯窗口放到 3~5 年，一次性回填即可支撑全市场个股的筹码分布计算。

### 路线 B：补个股资金流的**分档**与**历史回补**

- 东财 `ak.stock_individual_fund_flow(stock, market)` **有日度历史**，且带超大单/大单/中单/小单分档（项目 `stock_fund_flow.py:66` 的 `GET /today` 已在用，但只取了 `main_net` 与 `large_net` 两个数，未落库）。
- 改造后：`stock_fund_flow_daily` 增加 4 个分档列，回溯约 100+ 交易日。
- 收益：**净额口径从「推断的主力」升级为「大单结构」**，并能算出更细的「超大单加权均价」。

### 路线 C：补席位与逐笔（成本最高）

- 龙虎榜 / 营业部席位历史（当前只有 1 天）；
- 逐笔成交按日归档（当前可按需拉取但不落库）。

只有在需要做「事件级复盘」（谁在哪一天通过哪个营业部买了多少）时才值得做。

## 六、不确定项

1. `migrations/README.md` 提到库里有 40+ 张无 ORM 声明的表，不排除存在仓库外写入的隐藏表；但仓库内**无任何**筹码/股东/逐笔/融资融券的建表或写入代码。
2. `board_fund_flow_daily` 的 `super_large_net_inflow` 仅 65 行有值，其余 3 270 行为 NULL —— 是采集时上游就没返回，还是落库被丢弃，未逐行确认。
3. `icost_indicators`（CYC∞）最新只到 **2026-06-24**，已停更近 3 个月；且前端未发现展示入口。
4. 现有 `volume_profile.py` 的 POC/VAH/VAL 是否参与任何策略评分，注释自称「参考用，不作策略硬门槛」，但 `confluence_zones.py` / `pattern_tactical.py` 有基于 VP 的加减分文案，未逐行核算。
