01分层架构总览

系统是单仓库、多进程的单体多模块架构：三个 Web 服务 + 一个无端口的采集引擎 + 一个推送调度进程，共享同一个 PostgreSQL 库。

02数据流链路

采集在 backend_core 独立进程内跑，策略在收盘后定时预计算并把结果落成信号表；backend_api 只读这些结果对外提供接口，互不阻塞。

03部署拓扑与端口

用户站与管理端同域部署：Nginx 按路径分流，/admin/ 反代时剥掉前缀并对 SPA 深链回退到 index.html。两端登录态用不同的 localStorage 键名隔离。

同域登录隔离：用户站用 localStorage.access_token，管理端用 admin_token，键名不同、互不清理；两个 JWT 共用同一密钥但 users 与 admins 分表。详见 docs/prod/同域用户站与管理端登录说明.md。

08待处理风险

梳理架构时顺带发现的工程风险，按严重度排序。为避免扩散，此处不复述任何密钥明文，只给位置。

风险位置说明建议
高 数据库口令明文deploy_config.json 的 database.password明文存放且随仓库分发/打包移出仓库，改由环境变量注入
高 文档含明文口令docs/prod/环境说明.md运维文档里直接写了连接口令改为占位符，口令走密钥管理
高 JWT 占位密钥deploy_config.json 的 security.jwt_secret仍为默认占位串生产环境必须覆盖为强随机值
中 固定默认重置密码backend_api/admin/users.py 中「重置密码」接口重置后是固定常量口令改为随机口令 + 首次登录强制修改
中 迁移无版本账本migrations/*.py（60+）按文件修改时间执行，可能漏跑或乱序引入 Alembic 或迁移记录表
中 CORS 过宽backend_api/main.py白名单叠加局域网正则生产环境收紧为明确域名
低 死代码误导app_complete.py、main_enhanced.py、main_simple.py、market_routes_*.py多个未使用的备用入口与旧路由文件清理，避免新同学误读入口
